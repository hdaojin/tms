# competition_standards APP 用户手册总览

## 1. 功能定位

competition_standards APP 在系统中的展示名称为“赛训标准体系”。

它不是用来录入某一届比赛现场数据的，而是维护一套长期复用、跨届次稳定的标准底座。可以把它理解为“赛事类型 + 标准赛项 + 标准模块版本 + 训练周期 + 能力分析口径”的组合。

它解决的核心问题是：

- 同一个标准赛项可以跨多届赛事重复使用，不需要每届都重新定义基础结构。
- 训练周期直接归属于赛训标准体系，并绑定一个标准赛项和一版标准模块体系。
- 训练日志、考核、技能点等业务数据都通过训练周期或标准模块回到同一套长期标准口径。
- 某一届官方模块与长期标准不完全一致时，可由 competitions 中的映射关系完成对齐。

## 2. 适用角色

### 2.1 后台管理员

负责维护长期稳定的标准结构，包括：

- 赛事类型
- 标准赛项
- 标准模块版本
- 训练周期
- 标准模块
- 能力主线
- 标准模块能力主线映射

### 2.2 业务使用人员

通常不直接在后台维护标准体系，但会在其他 APP 中使用这些数据，例如：

- 在训练日志中选择训练周期和标准模块
- 在考核中选择训练周期，并按该周期的标准模块版本创建考核模块
- 在技能点管理中按标准模块组织专题和考点
- 在 competitions 中把某一届官方模块映射回标准模块和能力主线

## 3. 核心概念

### 3.1 赛事类型

赛事类型是上位分类，用来表达“这是什么类型的赛事”，例如世界技能大赛、全国职业院校技能大赛。

### 3.2 标准赛项

标准赛项是可长期复用的赛项模板，例如“网络系统管理”。它不是某一届赛事里的实际赛项，而是跨届次可复用的标准对象。

### 3.3 标准模块版本

标准模块版本表示某个标准赛项在某一版标准下的模块体系。

当下一届标准发生变化时，应新建新的标准模块版本，而不是直接覆盖旧版本。

### 3.4 训练周期

训练周期表示围绕某个标准赛项、某一版标准模块体系开展的一段训练周期。

每个训练周期必须选择：

- 标准赛项
- 标准模块版本
- 开始日期
- 状态

训练日志和考核都必须归入某个训练周期。选择模块时，也只能选择该周期绑定的标准模块版本下的模块。

### 3.5 标准模块

标准模块是系统内部长期复用的模块对象。traininglogs、assessments、skills 等 APP 依赖的都是标准模块。

### 3.6 能力主线

能力主线是比标准模块更稳定的一层长期分析口径。它回答的是“这些模块长期来看属于哪一条能力方向”。

不同版本的标准模块，可以共享同一条能力主线。

### 3.7 标准模块能力主线映射

这张映射表用来把标准模块挂到能力主线上。它解决的是“标准模块如何进入长期分析口径”的问题。

## 4. 业务关系链

competition_standards 的核心关系可以按下面这条链路理解：

1. 先定义赛事类型。
2. 在赛事类型下维护标准赛项。
3. 在标准赛项下维护能力主线。
4. 在标准赛项下按版本维护标准模块版本。
5. 在标准模块版本下维护标准模块。
6. 把标准模块映射到能力主线。
7. 围绕标准赛项和标准模块版本创建训练周期。

如果继续往 competitions APP 延伸，这条链会变成：

1. 具体赛事属于某个赛事类型。
2. 具体赛项等于“具体赛事 + 标准赛项”。
3. 本届官方模块属于某个具体赛项。
4. 本届官方模块再映射到标准模块，必要时直接映射到能力主线。

这也是为什么 competition_standards 负责“长期标准与训练周期”，competitions 负责“届次落地与归档”。

## 5. 与其他 APP 的关系

### 5.1 与 competitions 的关系

- competition_standards 维护长期标准底座和训练周期。
- competitions 维护某一届赛事的真实落地数据。
- competitions 中的具体赛项会引用 competition_standards 中的标准赛项。
- competitions 中的本届官方模块会通过映射关系对齐到标准模块和能力主线。
- 训练周期与具体赛项之间的“主目标赛项 / 参考赛项”关系由 competitions 的训练周期目标记录保存。

### 5.2 与 traininglogs、assessments 的关系

- 训练日志必须选择训练周期。
- 考核必须选择训练周期。
- 训练日志和考核模块选择的标准模块，必须属于该训练周期绑定的标准模块版本。

这样可以保证同一周期内的训练记录、考核资料和成绩使用同一套标准口径。

### 5.3 与 skills 的关系

skills 使用标准模块组织专题、技能点和考点。它不直接使用某一届官方模块。

## 6. 推荐维护顺序

如果你要新建一套赛训标准体系，建议按以下顺序操作：

1. 创建赛事类型。
2. 创建或复用标准赛项。
3. 为该标准赛项建立能力主线。
4. 创建新的标准模块版本。
5. 在该版本下录入标准模块。
6. 配置标准模块能力主线映射。
7. 创建训练周期，并绑定标准赛项和标准模块版本。

## 7. 常见判断题

### 7.1 什么情况要新建标准模块版本？

当模块数量、编号、名称、边界发生变化时，应新建新的标准模块版本。

### 7.2 什么情况不该直接修改旧版本？

如果旧版本已经被训练周期、训练记录、考核或技能点引用，就不应直接覆盖旧版本，否则会破坏历史口径。

### 7.3 为什么训练日志和考核都要选择训练周期？

训练周期锁定了“标准赛项 + 标准模块版本”。这样训练和考核不会混用不同版本的模块。

### 7.4 为什么这个 APP 不直接维护选手、代表队、成绩？

因为这些都属于某一届赛事的业务数据，不属于长期标准底座，应在 competitions 等业务 APP 中维护。
