# marking APP 总览

## 1. 功能定位

marking APP 负责评分方案、评分点、CMP 结果包和评分点级结果的归档分析。

它不负责执行评分命令、不部署竞赛环境，也不管理自动评分 runner。竞赛或考核实施过程应由 CMP 完成；TMS 只接收有长期价值的评分表、结果数据和报表。

## 2. 页面入口

入口位于“竞赛”区块中的“评分归档”。

常见入口包括：

1. `/marking/`：查看已导入的评分方案。
2. `/marking/schemes/import/`：导入新版单模块评分表。
3. 竞赛具体赛项详情页：从“本届官方模块”进入导入或查看评分归档。
4. 考核详情页：从“考核模块”进入导入或查看评分归档。

入口是否显示取决于当前用户权限。无权限用户不会看到导入入口。

## 3. 评分表导入

当前只支持新版单模块 xlsx 模板，主工作表必须名为 `Marking Scheme Import`。

导入前系统会校验：

1. 表头语义完整，大小写和单元格换行可忽略，但规范化后必须与模板一致。
2. 模块 `ID` 必须与绑定的竞赛官方模块或考核模块编号一致。
3. 子评分项编号必须按模块前缀连续递增，例如 A1、A2、A3。
4. M 类型评分点必须包含类型、描述、操作或命令、期望结果和分值。
5. J 类型评分点必须包含主行和 0/1/2/3 四个分档说明。
6. `Max Mark` 必须可计算，评分点分值合计必须同时等于 `Total Marks:` 和模块 `Mark`。

校验失败时不会保存原始文件，也不会创建评分方案。用户需要修复表格后重新上传。

## 4. 保存内容

导入成功后系统保存：

1. 原始 xlsx 文件、SHA256、解析器版本、导入人和绑定对象。
2. 评分方案、子评分项、评分点和 J 类型分档。
3. 评分点到技能树节点的人工映射关系。

系统不长期保存每个原始单元格或原始行的结构化副本。原始 xlsx 是审计证据。

## 5. CMP 结果包

CMP 回传结果使用 JSON 结果包。JSON 包可包含：

1. 目标评分方案。
2. 参评对象。
3. 评分点得分和证据摘要。
4. 可选的竞赛官方总成绩、排名和奖项。

导入后，评分点级结果进入 marking；竞赛官方总成绩可同步写入 competitions 的 `CompetitionResult`。

## 6. 与技能树的关系

评分表导入后只形成评分点/考点池，不会自动生成正式技能树。

用户应先在 skilltrees 中维护标准模块级技能树，然后在 marking 中把评分点人工映射到一个或多个技能节点，并设置权重和主技能。

## 7. 分析口径

训练分析使用评分点级结果汇总：

1. 模块总分。
2. 子评分项得分。
3. 评分点得失分。
4. 映射到技能节点后的技能得失分。
5. 个人弱项、模块弱项和训练计划参考数据。

竞赛官方排名和奖项仍以 competitions 的 `CompetitionResult` 为准。
