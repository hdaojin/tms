# 评分管理

## 功能概述

评分管理从 AssessmentModule 的评分标准资料执行“解析 → 预览 → 确认”，生成评分方案、评分子项、评分点和评价分档。每个确认后的评分点自动生成已批准考点证据。

## 导入流程

1. 在竞赛与考核模块上传“评分标准”类型资料。
2. 进入“导入评分标准”，选择评分标准资料和已启用解析器。
3. 核对模块、总分、评分子项、评分点和 J 分档预览。
4. 确认生成评分方案；若已有真实评分结果，系统禁止覆盖原方案。
5. 在对应竞赛与考核中维护选手，再录入或导入真实评分结果。评分结果直接关联该场竞赛与考核的选手，不再维护重复的“参评对象”。

导入确认页会同时核对评测模块配置总分、解析器识别总分、评分方案总分和评分点分值合计。模块未配置总分时显示警告；已配置值或评分标准内部数值不一致时禁止确认。

解析器是随代码发布的实现能力，管理员只能在 Django Admin 中配置代码 Registry 已存在的解析器是否启用、显示名称、排序和默认项，不能通过数据库新增尚无实现的解析器。新环境执行 `uv run manage.py bootstrap_tms` 后会创建当前 Registry 配置；已有环境发现新解析器时默认保持停用且不替换现有默认项。若没有启用的解析器，导入页面会明确提示先执行 Bootstrap 或由管理员完成配置。

## 在线评分

有权维护对应技术领域评分数据的教练可从评分方案进入在线评分工作台：

1. “按选手”视角用于给一名选手逐项录分；
2. “按评分点”视角用于给全部选手快速录入同一评分点；
3. 每次提交只更新当前工作台区域，并同步刷新评分进度、未完成项和累计得分率；
4. 修改已有得分时可填写原因，系统保留原值、新值、修改人和修改时间；
5. 勾选“确认本项得分”后记录确认人和确认时间。已确认得分被修改时必须重新确认。

比赛期间，选手不会在该工作台看到其他选手成绩或实时排名。

## 结果与 Skill

评分结果不直接写入 Skill。系统沿“评分结果 → 评分点 → 已批准 Evidence → 已批准映射 → Skill”按当前映射权重动态折算得分、失分、得分率和趋势；同一评分点至少出现两次失分时，可在 Skill 详情作为“历史重复失分”供教练复核。该分析受评分结果与 Evidence 对象范围共同限制，不保存掌握度真值。

## 注意事项

- 出厂默认解析器严格解析 CMP 单模块 `.xlsx` 评分标准；实际默认项以当前环境的解析器配置为准。
- 来源评分标准必须属于目标 AssessmentModule。
- 导入确认可安全重复执行；已经确认的同一导入记录返回原评分方案。
