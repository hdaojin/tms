# scoring 评分管理

## 功能概述

scoring 用于评分表导入、评分方案查看、参评对象维护和评分结果记录。评分表导入采用“上传解析 -> 预览确认 -> 生成评分方案”的流程：解析成功后先保存导入记录和原文件，用户确认后才生成或覆盖评分方案、评分子项、评分点、评价分档，并为每个评分点自动生成已通过考点证据。

## 入口路径

- 顶部导航：竞赛
- 侧边栏：竞赛 -> 评分管理 -> 评分方案 / 导入评分表 / 新增参评对象 / 录入评分结果
- 前台路径：`/scoring/`

## 权限

- 登录用户可查看评分方案和评分点。
- 导入评分表、确认生成评分方案、维护参评对象和录入结果需要 `scoring.maintain_scoring` 权限包中的对应权限。
- 解析器展示名称、别名、说明、启用状态、默认状态和排序由管理员在后台维护；解析规则由系统代码注册，不能在后台新增或修改。

## 关键概念

- 解析器：系统内置的评分表解析规则。当前默认解析器为 `cmp_single_module_v1`，用于严格解析 CMP 单模块评分表。
- 导入记录：保存解析成功后的原文件、解析器展示信息快照、raw 单元格证据、字段映射、校验报告和结构化预览数据。
- 评分方案：某个事件模块的评分表结构化结果。
- 评分子项：评分表中的子评分项，例如 `A1`、`A2`。
- 评分点：实际计分条目，会生成考点证据。
- 评价分档：J 类型评分点的 0/1/2/3 四档说明。
- 参评对象：事件参与人员、系统用户或外部编号三者之一。
- 评分结果：参评对象在评分点上的得分。

## 导入流程

1. 进入“导入评分表”，选择事件模块、解析器和 `.xlsx` 文件。
2. 可在导入页下载当前解析器的示例模板。
3. 上传后系统严格解析模板内容；失败时会在表单页一次性展示所有阻断错误，不保存原文件，也不创建导入记录。
4. 解析成功后进入预览页，核对模块信息、解析器信息、源文件、总分校验、子评分项、评分点和 J 分档。
5. 点击“确认生成评分方案”后，系统生成或覆盖评分方案。
6. 如果同一事件模块和模块代码已经存在评分方案且没有评分结果，允许覆盖；如果已有评分结果，则阻断确认。

## 严格模板规则

- 当前只支持 CMP 单模块评分表，不自动兼容简化格式。
- 工作表必须包含 `Marking Scheme Import`。
- 标题行不能为空。
- 模块定义必须包含 `ID / Name / Mark`，并且模块 `ID` 必须等于所选事件模块代码。
- 评分细则表头按语义定位，不按固定列号；表头忽略大小写并折叠多余空白后必须与模板一致。
- 内容字段不忽略大小写；会折叠多余空白并保留换行。
- 子评分项编号必须按模块 ID 连续递增，例如 `A1`、`A2`。
- 子评分项标题行只允许填写 `Sub Criterion ID`、`Sub Criterion Name or Description`、`Day of Marking`。
- `Day of Marking` 只原样保存，本轮不限制实际评分日期。
- M 类型评分点必须填写类型、评分点描述、命令或操作、Requirement 和 Max Mark。
- J 类型评分点必须填写类型、评分点描述、命令或操作、Max Mark，并紧跟 0/1/2/3 四档分档行；J 本体行的 Requirement 不强制。
- `Max Mark`、`Total Marks`、模块 `Mark` 必须是可计算数值；公式必须能读到缓存数值。
- 明细分值总和必须同时等于 `Total Marks:` 和模块 `Mark`。
- `WSOS Section` 只保存在 raw 快照中；`Calculation Row` 会保存在 raw 快照并展示到评分点表。
- 模板规定区域外存在非空业务内容会导致解析失败。

## 注意事项

- CMP 模板中评分点不需要单独填写 `aspect id`；系统会按子评分项自动生成 `A1.1`、`A1.2` 这样的评分点编号。
- 评分点结果不直接写入技能点，必须通过考点证据和技能映射折算。
- 解析器展示文案会保存到导入记录中，管理员后续改名不会影响历史导入审计。
