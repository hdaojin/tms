# curriculum APP 用户手册总览

## 1. 功能定位

curriculum APP 当前在系统中的展示名称为“赛训标准体系”。

它不是用来录入某一届比赛现场数据的，而是用来维护一套长期复用、跨届次稳定的标准底座。可以把它理解为“赛项标准库 + 模块标准库 + 长期分析口径库”的组合。

它解决的核心问题是：

- 同一个赛项可以跨多届赛事重复使用，不需要每届都重新定义基础结构。
- 标准模块可以被 trainingcycles、traininglogs、assessments、skills 等 APP 复用。
- 当某一届官方模块口径与长期标准不完全一致时，仍然可以通过映射关系完成对齐。

## 2. 适用角色

### 2.1 后台管理员

负责维护长期稳定的标准结构，包括：

- 赛事类型
- 标准赛项
- 标准模块版本
- 标准模块
- 能力主线
- 标准模块能力主线映射

### 2.2 业务使用人员

通常不直接在 curriculum APP 中录入数据，但会在其他 APP 中间接受到这里的影响，例如：

- 在备赛周期中选择标准赛项和标准模块版本
- 在训练记录中选择标准模块
- 在考核中按标准模块录入成绩
- 在技能点管理中按标准模块组织专题和考点

## 3. 核心概念

### 3.1 赛事类型

赛事类型是上位分类，用来表达“这是什么类型的赛事”，例如世界技能大赛、全国职业院校技能大赛。

### 3.2 标准赛项

标准赛项是可长期复用的赛项模板，例如“网络系统管理”。它不是某一届赛事里的实际赛项，而是跨届次可复用的标准对象。

### 3.3 标准模块版本

标准模块版本表示某个标准赛项在某一版标准下的模块体系。

它表达的是“这个赛项在这一版标准里分成哪些模块”。当下一届标准发生变化时，应新建新的标准模块版本，而不是直接覆盖旧版本。

### 3.4 标准模块

标准模块是系统内部长期复用的模块对象。traininglogs、assessments、skills 等 APP 依赖的，都是标准模块。

### 3.5 能力主线

能力主线是比标准模块更稳定的一层长期分析口径。它回答的是“这些模块长期来看属于哪一条能力方向”。

不同版本的标准模块，可以共享同一条能力主线。

### 3.6 标准模块能力主线映射

这张映射表用来把标准模块挂到能力主线上。它解决的是“标准模块如何进入长期分析口径”的问题。

## 4. 业务关系链

curriculum 的核心关系可以按下面这条链路理解：

1. 先定义赛事类型。
2. 在赛事类型下维护标准赛项。
3. 在标准赛项下维护能力主线。
4. 在标准赛项下按版本维护标准模块版本。
5. 在标准模块版本下维护标准模块。
6. 再把标准模块映射到能力主线。

如果继续往 competitions APP 延伸，这条链会变成：

1. 具体赛事属于某个赛事类型。
2. 具体赛项等于“具体赛事 + 标准赛项”。
3. 本届官方模块属于某个具体赛项。
4. 本届官方模块再映射到标准模块，必要时直接映射到能力主线。

这也是为什么 curriculum 负责“长期标准”，competitions 负责“届次落地”。

## 5. 与其他 APP 的关系

### 5.1 与 competitions 的关系

- curriculum 维护长期标准底座。
- competitions 维护某一届赛事的真实落地数据。
- competitions 中的具体赛项会引用 curriculum 中的标准赛项。
- competitions 中的本届官方模块会通过映射关系对齐到 curriculum 中的标准模块和能力主线。

### 5.2 与 trainingcycles 的关系

当前入口：侧边栏“训练” -> “备赛周期”。

备赛周期会选择：

- 标准赛项
- 标准模块版本

这意味着某个备赛周期是围绕哪一个赛项、哪一版标准模块体系开展训练的。

### 5.3 与 traininglogs、assessments、skills 的关系

这些 APP 使用的都不是“本届官方模块”，而是“标准模块”。

这样做的好处是：

- 不会因为某一届官方命名变化而打断长期积累。
- 同一赛项跨届次的数据可以持续沉淀到统一标准口径下。
- 后续分析时既能看标准模块，也能上卷到能力主线。

## 6. 推荐维护顺序

如果你要新建一套赛训标准体系，建议按以下顺序操作：

1. 先创建赛事类型。
2. 创建或复用标准赛项。
3. 为该标准赛项建立能力主线。
4. 创建新的标准模块版本。
5. 在该版本下录入标准模块。
6. 配置标准模块能力主线映射。

## 7. 常见判断题

### 7.1 什么情况要新建标准模块版本？

当模块数量、编号、名称、边界发生变化时，应新建新的标准模块版本。

### 7.2 什么情况不该直接修改旧版本？

如果旧版本已经被备赛周期、训练记录、考核或技能点引用，就不应直接覆盖旧版本，否则会破坏历史口径。

### 7.3 能力主线和标准模块是什么关系？

能力主线是长期分析口径，标准模块是某一版标准下的具体实现。标准模块更具体，能力主线更稳定。

### 7.4 为什么这个 APP 不直接维护选手、代表队、成绩？

因为这些都属于某一届赛事的业务数据，不属于长期标准底座，应在 competitions 等业务 APP 中维护。
