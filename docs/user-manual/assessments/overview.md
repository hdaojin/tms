# 竞赛与考核

## 功能概述

竞赛与考核统一管理正式竞赛、选拔赛、交流赛、模拟赛、训练考核和训练测试，以及模块、参与人员和私有业务资料。

“竞赛与考核类型”和“赛事角色”由管理员在 Django Admin 中维护。目录项的代码是稳定机器标识，已有业务引用后不应修改；显示名称、排序和启用状态可以调整。停用的类型或角色不再提供给新建业务选择，但历史记录及其编辑页面仍保留原值。

## 入口与资料上传

- 顶部“竞赛与考核”只保留“竞赛与考核”“长期赛事人员”“赛事角色配置”三个业务入口。
- “长期赛事人员”维护可跨届复用、不可登录的外部赛事人员；“赛事角色配置”维护角色名称及稳定类别。临时人员仍可在单场 Assessment 内直接录入。
- 资料从竞赛、考核或模块上下文上传，不再使用全局“资料资产”入口。
- 支持试题、评分表、评分标准、评分脚本、结果文件和其他附件。
- “模块与资料”中的文件名进入附件详情页，独立的“下载”按钮仍可直接下载文件。
- PDF、常见图片和 UTF-8 纯文本可以在详情页在线预览；Office、压缩包等文件显示基本信息并提供下载。
- 文件详情、在线预览和下载都必须经过登录、权限和对象范围检查。

Assessment 详情采用统一工作台，按“概览、模块与资料、人员、评分、最终结果、考点与技能、分析”组织。各标签只显示当前账号有权查看的模块和业务数据；普通教练不会看到其他技术领域的评分方案、结果或考点证据。

新增模块、上传资料、导入评分标准、录入评分结果和 Evidence 映射均从具体 Assessment 或 Module 工作台进入，不再作为主导航中的模型级菜单。

## 教练流程

1. 创建 Assessment 并选择技能项目、类型、日期和可选训练周期。
2. 创建评测模块，关联一个或多个技术领域；跨领域模块应显式分配负责教练。
3. 维护参与人员。
4. 上传模块评分标准，并从评分管理进入解析、预览和确认。
5. 回到 Assessment 工作台，从“评分”进入对应模块的在线评分；从“考点与技能”查看评分点证据及 Skill 映射。

## 生命周期与最终结果

- 生命周期操作可从工作台“概览”显式执行：草稿可发布，已发布可启动，进行中可完成；已完成的 Assessment 可在成绩发布后归档。取消快捷操作适用于草稿、已发布或进行中的 Assessment。
- 具备维护权限的人员也可从 Assessment 编辑页直接把“状态”修改为草稿、已发布、进行中、已完成、已归档或已取消中的任意状态，不受当前状态限制。该人工修改不会伪造或清空独立保存的实际启动、完成时间。
- “最终结果”先显示按详细评分结果实时汇总的计算预览；预览不会自动成为官方结果。
- 完成 Assessment 后，授权人员可生成或更新待确认结果，维护名次、多种成绩表示和多个奖项，再逐条确认正式结果。
- 发布成绩前，所有选手都必须已有已确认结果和至少一项成绩。发布后结果锁定，普通选手只能看到自己的最终成绩、名次和奖项，不能查看其他选手的结果或评分点明细。
- 计划时间与实际启动、完成时间分别保存；完成 Assessment 与发布成绩是两个独立动作。

## Skill 证据分析

- “分析”标签按当前账号可查看的模块汇总完成率和得分率；只有同时具有“查看全部评分结果”和“查看考点证据”权限时，才显示 Skill 得分、失分和得分率。
- Skill 汇总只使用已批准 Evidence 与已批准映射，并按当前映射权重从真实评分结果动态计算。点击 Skill 可进入其跨 Assessment 历史趋势和重复失分证据。
- 普通选手不会从分析页看到全体汇总、其他选手成绩或 Skill 表现明细。
- 分析结果不保存为“掌握度”，也不会自动创建或调整训练计划。

## 注意事项

- 模块和资料必须属于同一 Assessment。
- 同一评测、模块和资料类型下，新上传版本必须大于现有最高数值版本；相同内容可以用更高版本上传。历史版本不参与比较。


## 资料自动命名与版本

上传时无需填写标题或文件编号。系统按评测、技能项目、模块及资料类型生成标题，文件名为：

`{评测代码}-{项目代码}-{模块代码}-{类型}-v{版本}-{YYYY.MM.DD}.{扩展名}`

例如：`WS2026-ITNSA-A-TestProject-v1.0-2026.09.05.pdf`。公共资料的模块标识为 `GEN`。

- 代码仅允许英文字母和数字，保留大小写：评测 1–20 位、技能项目 1–12 位、模块 1–8 位。模块不能使用保留代码 `GEN`（不区分大小写）。评测、项目和模块代码创建后均不可修改，创建时请确认；名称仍可修改。启用代码锁定前需检查历史代码，发现不合规数据时由管理员制定修正方案，不自动改码。
- 版本必填，必须带一位小数，例如 `1.0`、`1.1`、`2.0`；整数部分最多 8 位。不接受 `1`、`1.00`、`v1.0` 或文字。首次至少 `1.0`，后续严格递增，可以跳号。
- 选择评测、模块和类型后，页面显示最高版本及建议版本；仍需手动填写，保存时再次校验。
- 同一模块下同类型文件共用一条版本序列，即使内容不同也必须使用更高版本；更换日期或扩展名不能重复使用版本号。
- 资料日期默认当天，可以修改为实际资料日期。新文件的展示、预览、下载与存储名称一致，原始文件名仍保留供追溯。
- 试题使用 `TestProject`，评分标准使用 `MarkingScheme`，技术文件使用 `TechnicalDescription`，评分脚本使用 `ScoringScript`，成绩或结果文件使用 `ResultFile`，其他附件使用 `Attachment`。
- 不再提供“评分表”类型，历史评分表归入其他附件；评分方案仍只从评分标准导入。
- 历史文件不重命名、不补版本，不参与新版本比较。已保存的新名称也不会随评测、项目或模块改名而变化。
- 后台新增资料会转到同一上传页，已保存资料的后台字段只读，更新文件请上传更高版本。


## 磁盘存储目录

新上传文件按以下业务目录保存，便于按评测查找和整理备份：

`{PRIVATE_MEDIA_ROOT}/assessments/{评测代码}/{项目代码}/{模块代码或GEN}/{类型}/{规范文件名}`

例如：`assessments/WS2026/ITNSA/A/TestProject/WS2026-ITNSA-A-TestProject-v1.0-2026.09.05.pdf`。

各版本直接存放在类型目录中，不再建立正式 UUID 目录或独立版本目录。历史文件保留原存储位置，不自动搬迁。

上传先写入同一私有存储根目录下的 `.tmp` 临时目录，完成写入后再发布到正式位置；正常失败会清理本次临时文件及已发布文件。目标文件存在时明确拒绝保存，不覆盖、不追加随机后缀。发布过程要求存储文件系统支持同卷硬链接，不支持时上传会显示存储错误。

文件必须继续通过有权限检查的页面下载或预览，不能直接公开私有目录。复制评测目录仅备份文件内容；恢复权限、版本关系和评分引用还需要数据库备份。代码锁定覆盖表单、后台和模型保存入口，业务代码不得通过批量更新或直接 SQL 修改这些代码。
