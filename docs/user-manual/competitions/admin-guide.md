# competitions APP 后台管理员手册

## 1. 适用对象

本手册适用于负责 competitions 届次数据维护的后台管理员。长期标准底座由 competition_standards APP 维护，本手册中涉及赛事类型、标准赛项、标准模块版本、标准模块和能力主线的内容，均以 competition_standards 后台入口为准。

后台管理员的工作重点是：

- 维护基础字典与复用主数据
- 建立某一届赛事及其具体赛项
- 对接 competition_standards 中已经建立的能力主线与标准模块体系
- 配置本届官方模块与标准模块、能力主线之间的映射关系

## 2. 后台维护范围

当前应由后台维护的数据分为两类：

1. competition_standards 维护长期标准：赛事类型、标准赛项、能力主线、标准模块版本、标准模块、标准模块与能力主线的映射关系。
2. competitions 维护届次落地：具体赛事、具体赛项、本届官方模块、官方模块与标准模块 / 能力主线的映射关系。

说明：

- “本届官方模块”现在有两个后台入口：既可以从独立的“本届官方模块”后台进入，也可以从“具体赛项”列表或详情中的官方模块入口直达。

以下数据不建议在后台作为日常主入口维护：

1. 代表队
2. 选手
3. 专家
4. 岗位人员
5. 竞赛总成绩

这些数据以 competitions 前台录入流程为主。

## 3. 推荐维护顺序

建议后台始终按以下顺序操作：

1. 在 competition_standards 中创建赛事类型。
2. 在 competition_standards 中创建或复用标准赛项。
3. 在 competition_standards 中创建能力主线。
4. 在 competition_standards 中创建标准模块版本。
5. 在 competition_standards 中创建标准模块。
6. 在 competition_standards 中配置标准模块与能力主线映射。
7. 在 competitions 中创建具体赛事。
8. 在 competitions 中创建具体赛项。
9. 在 competitions 中录入本届官方模块。
10. 在 competitions 中配置本届官方模块与标准模块、能力主线映射。

说明：

- 不建议先建官方模块再补建标准模块。
- 不建议跳过标准模块版本，直接在旧标准模块上原地改名或改编号。

## 4. 常见任务

### 4.1 创建新的赛事类型

适用场景：

- 系统中还没有某类竞赛的上位分类时。

需要关注的字段：

1. 赛事代码
2. 赛事名称
3. 级别
4. 权重
5. 描述

结果确认：

- 能在赛事类型列表中看到新记录。
- 后续创建具体赛事时可以选择该赛事类型。

### 4.2 创建或复用标准赛项

适用场景：

- 新一届赛事需要沿用已有标准赛项。
- 系统中第一次出现某个赛项模板。

注意事项：

- 标准赛项是全局赛项模板库，不属于某一届赛事。
- 如果赛项本身没有变化，优先复用已有标准赛项，不要重复建多个名字相近的条目。
- 历史旧库升级后，少量旧条目可能已经被不同赛事类型复用。系统允许继续查看和编辑这些已存在的历史具体赛项，但新建具体赛项时，仍应优先选择与当前赛事类型一致的标准赛项。

### 4.3 创建新的标准模块版本

适用场景：

- 下一届标准发生变化，例如模块增加、减少、改名、改编号。

推荐做法：

1. 在原标准赛项下新建一个新的标准模块版本。
2. 用新版本名称标识，例如“2026 版”。
3. 将新版本设置为当前启用。
4. 在新版本下维护新的标准模块。

禁止做法：

- 不要直接修改旧版本中的模块编号或名称。
- 不要为了下一届变化而删除旧版本中的历史模块。

### 4.4 创建标准模块

适用场景：

- 某个标准赛项的当前标准模块版本已经建立，需要录入该版本下的模块明细。

需要关注的字段：

1. 所属标准赛项
2. 所属标准模块版本
3. 模块编号
4. 模块名称
5. 描述
6. 显示顺序

结果确认：

- 模块出现在对应标准赛项的当前版本中。
- traininglogs、assessments、marking、skilltrees 等 APP 的新录入入口可基于当前版本使用这些模块。

### 4.5 创建能力主线

适用场景：

- 需要为某个标准赛项建立长期稳定的分析主线，例如 A、B、C、D 这类长期口径。

需要关注的字段：

1. 所属标准赛项
2. 主线代码
3. 主线名称
4. 描述
5. 显示顺序
6. 是否启用

结果确认：

- 该能力主线可在标准模块和本届官方模块的映射表单中被选择。
- 同一标准赛项下不会出现重复主线代码。

### 4.6 配置标准模块与能力主线映射

适用场景：

- 当前标准模块已经录入，需要建立长期分析口径。

规则说明：

1. 同一标准模块如果配置能力主线映射，应当有且仅有一条主映射。
2. 能力主线必须属于同一个标准赛项。
3. 如存在拆分关系，可以补辅助映射和权重。

### 4.7 创建具体赛事

适用场景：

- 系统中开始管理某一届真实发生的竞赛。

需要关注的字段：

1. 所属赛事类型
2. 赛事名称
3. 赛事编号
4. 开始日期与结束日期
5. 举办地点
6. 描述

结果确认：

- 竞赛列表中能看到该赛事。
- 赛事详情页可展示该赛事的背景描述或补充说明。
- 可继续为该赛事创建具体赛项。

### 4.8 创建具体赛项

适用场景：

- 某一届赛事确定包含某个标准赛项时。

需要关注的字段：

1. 所属赛事
2. 标准赛项
3. 赛项文件
4. 本届赛项描述

结果确认：

- 赛事详情页可看到该具体赛项。
- 具体赛项后台页可维护“已关联代表队”范围，供前台录入选手和专家时选择。
- 前台可围绕该具体赛项录入代表队、人员和总成绩。

### 4.9 录入本届官方模块

适用场景：

- 某一届比赛公布了官方模块编号与名称。

录入原则：

1. 官方模块编号按官方原始编号填写。
2. 官方模块名称按官方原始名称填写。
3. 先录模块本身，再去维护映射关系。

### 4.10 配置官方模块与标准模块、能力主线映射

适用场景：

- 已录入本届官方模块，需要告诉系统它对应哪个或哪些标准模块。

规则说明：

1. 官方模块到标准模块的映射，应有且仅有一个主映射。
2. 官方模块到能力主线的映射可以为空；但如果配置，也应只有一个主映射。
3. 映射的标准模块和能力主线都必须属于当前具体赛项对应的标准赛项。
4. 如果某个官方模块无法诚实映射到标准模块，可以只配置能力主线映射，用于长期分析归口。

推荐操作：

1. 先配置标准模块主映射。
2. 再决定是否需要补辅助标准映射。
3. 如该官方模块存在例外分析口径，再配置直接能力主线映射。
4. 对特殊映射关系填写备注，方便后续分析和复核。

### 4.11 从具体赛项进入官方模块维护

适用场景：

- 你已经定位到某个具体赛项，准备集中维护该赛项的本届官方模块与映射。

推荐入口：

1. 先进入“具体赛项”后台列表。
2. 在目标记录的“官方模块入口”列点击“进入本届官方模块”。
3. 系统会直接打开当前具体赛项过滤后的模块列表。
4. 在模块列表中点击模块编号或模块名称进入编辑页，继续维护标准模块映射。

补充说明：

- 如果你想跨多个赛事统一排查模块，也可以直接使用独立的“本届官方模块”后台入口。
- 如果只是顺手补少量模块，仍可在具体赛项编辑页的 inline 区域直接维护。
- 现在“本届官方模块”区域会直接显示标准模块关系和能力主线关系，方便你在具体赛项页先做核对，再决定是否进入模块详情页继续编辑。

## 5. 后台完整示例流程

下面用一个完整示例说明后台管理员如何从零建立一届赛事。

### 5.1 示例场景

假设现在要在系统中建立“第 48 届世界技能大赛”的“网络系统管理”赛项，并且本届开始启用新的模块标准。

### 5.2 推荐操作顺序

1. 先检查系统中是否已有“世界技能大赛”这一赛事类型。
2. 检查“网络系统管理”是否已存在于标准赛项库中。
3. 先建立或检查该赛项的能力主线。
4. 如果下一届模块标准有变化，先新建新的标准模块版本。
5. 在新版本中录入新的标准模块。
6. 为标准模块补齐能力主线映射。
7. 创建“第 48 届世界技能大赛”这条具体赛事记录。
8. 在该赛事下创建“网络系统管理”具体赛项。
9. 按官方文件录入本届官方模块。
10. 为每个官方模块配置标准模块映射，必要时补直接能力主线映射。
11. 到前台检查该具体赛项详情页是否已经具备后续业务录入条件。

### 5.3 每一步要确认什么

第一步，确认赛事类型：

- 名称、代码、级别是否正确。
- 如果级别错了，前台代表队筛选会跟着错。

第二步，确认标准赛项：

- 优先复用已有标准赛项。
- 不要因为届次不同就重复创建同名标准赛项。

第三步，确认标准模块版本：

- 如果只是沿用旧标准，不需要新建版本。
- 如果模块数量、编号、名称、边界发生变化，就应新建版本。

第四步，确认标准模块：

- 模块编号和名称是否已按新标准录入。
- 当前启用的版本下模块是否完整。

第五步，确认具体赛事：

- 赛事名称、编号、时间和地点是否正确。
- 该赛事是否已经挂到正确的赛事类型下。

第六步，确认具体赛项：

- 具体赛事和标准赛项是否组合正确。
- 该赛项建立后，前台详情页就会有对应入口。

第七步，确认本届官方模块：

- 官方模块编号和名称要按官方原文录入。
- 不要直接把官方模块当成标准模块使用。

第八步，确认模块映射：

- 每个官方模块是否恰好有一条主映射。
- 映射目标是否都属于同一标准赛项。

第九步，确认前台可用性：

- 登录后打开赛事详情页，确认能看到新建的具体赛项。
- 打开具体赛项详情页，确认页面可正常显示官方模块区块。

## 6. 后台字段说明重点

### 6.1 标准模块版本的“当前启用”

同一标准赛项同一时刻只允许一套当前启用的标准模块版本。新版本启用后，旧版本会退役，但历史数据不会自动改挂。

### 6.2 模块映射中的“主映射”

主映射表示该本届官方模块当前最主要对应的标准模块，是很多展示和筛选逻辑的默认依据。

### 6.3 模块映射中的“权重”

权重用于表达某一官方模块与多个标准模块之间的相对对应关系，便于后续做更细粒度分析。

## 7. 常见错误与处理建议

### 7.1 误把下一届变化直接改在旧模块上

处理建议：

- 停止继续修改旧模块。
- 新建新的标准模块版本，并把变化放到新版本里。

### 7.2 把其他标准赛项的标准模块映射到当前官方模块

处理建议：

- 检查当前具体赛项对应的标准赛项。
- 只选择属于同一标准赛项的标准模块。

### 7.3 漏配主映射或配置了多个主映射

处理建议：

- 每个官方模块保留一条且仅一条主映射。
- 其余映射设为辅助映射。

### 7.4 后台已改主干数据，但前台使用人员还不知道

处理建议：

- 只要变更了页面入口、字段语义、录入顺序或权限逻辑，就应同步更新手册。
- 至少要同步修改总览页和受影响角色对应的操作手册。
