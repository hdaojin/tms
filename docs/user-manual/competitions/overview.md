# competitions APP 用户手册总览

## 1. 功能定位

competitions APP 用于管理竞赛相关信息，覆盖从赛事基础资料到前台业务补录的完整链路。

当前 competitions 的职责边界如下：

- 后台负责维护主干数据，包括竞赛类型、具体赛事、竞赛项目、模块主线、标准模块集、标准模块、具体赛项、本届官方模块及其映射关系。
- 前台负责补录业务数据，包括代表队、选手、专家、岗位人员和竞赛总成绩。
- 所有登录用户都可以查看竞赛列表、赛事详情和具体赛项详情。

当前后台中，“具体赛项模块”已经同时提供独立入口和从“具体赛项”直达的入口，便于集中维护重要模块数据。

当前模块体系已经升级为“四层结构 + 双映射分析层”：

1. 竞赛项目
2. 模块主线
3. 标准模块集与标准模块
4. 本届官方模块

其中，“标准模块主线映射”用于定义长期标准口径，“官方模块标准映射”和“官方模块主线映射”用于表达某一届比赛的真实官方口径与长期分析口径之间的关系。

## 2. 适用角色

### 2.1 后台管理员

负责建立和维护 competitions 的基础数据，为前台录入提供可复用的数据基础。

典型工作包括：

- 创建竞赛类型
- 创建具体赛事
- 维护竞赛项目和标准模块集
- 维护标准模块
- 创建具体赛项
- 维护本届官方模块
- 配置官方模块与标准模块的映射关系

### 2.2 前台业务录入人员

负责补录某一届赛事、某一具体赛项下的业务信息。

典型工作包括：

- 新增代表队
- 新增选手
- 新增专家
- 新增岗位人员
- 录入竞赛总成绩

### 2.3 普通登录用户

可以查看 competitions 的公开业务页面，包括竞赛列表、赛事详情和具体赛项详情，但不能进行录入。

## 3. 页面入口

当前 competitions APP 的前台菜单位于“竞赛”区块下，主要入口包括：

1. 竞赛列表
2. 新增代表队
3. 新增选手
4. 新增专家
5. 新增岗位人员
6. 录入竞赛总成绩

说明：

- 录入类入口是否显示，取决于当前用户是否具有对应的新增权限。
- 即使没有新增权限，只要已经登录，仍可查看竞赛列表和详情页面。

## 4. 关键概念

如果你只想快速查术语，不想在总览页逐段查找，建议直接阅读 [glossary.md](glossary.md)。

### 4.1 竞赛类型

竞赛类型表示某类竞赛的上位分类，例如世界技能大赛、全国职业院校技能大赛等。它定义了赛事级别等基础属性。

### 4.2 具体赛事

具体赛事表示某一届、某一次真实发生的竞赛，例如“第 47 届世界技能大赛”。

### 4.3 竞赛项目

竞赛项目表示一个可复用的项目库条目，例如某个技能赛项。它不直接绑定某一届赛事。

### 4.4 具体赛项

具体赛项表示“某一届具体赛事”与“某一个竞赛项目”的组合，是前台补录业务数据的核心对象。

### 4.5 标准模块集

标准模块集表示某个竞赛项目在某一版标准下的模块体系，例如“2025 版标准模块”“2026 版标准模块”。同一项目同一时刻只允许一套当前启用的标准模块集。

### 4.6 模块主线

模块主线表示一个长期稳定的分析主线，用于回答“这个模块大致属于哪一条能力主线”。它不是某一届比赛专属对象，也不等同于标准模块版本。

### 4.7 标准模块

标准模块是系统内部用于长期复用、被其他 APP 引用的模块对象。traininglogs、skills、assessments 等模块引用的都是标准模块，而不是某一届比赛的官方模块。

### 4.8 本届官方模块

本届官方模块表示某一届具体赛项中实际使用的模块编号和名称。它保存的是该届竞赛官方口径的数据。

### 4.9 模块映射

当前 competitions 中有三类模块映射：

1. 标准模块主线映射：把标准模块映射到模块主线。
2. 官方模块标准映射：把本届官方模块映射到一个或多个标准模块。
3. 官方模块主线映射：在必要时把本届官方模块直接映射到模块主线，适合 E 模块等难以诚实落到标准模块的场景。

### 4.10 代表队

代表队是可复用的全局主数据，带有层级属性，用于匹配赛事级别。

### 4.11 竞赛人员

竞赛人员是可复用的人员主档，选手、专家、岗位人员都可以基于该主档在不同赛事中重复使用。

### 4.12 选手、专家、岗位人员

这三类记录都属于“某一具体赛项下的人员记录”，它们引用可复用的竞赛人员主档，并附带当前赛事上下文信息。

### 4.13 竞赛总成绩

竞赛总成绩记录的是具体赛项下选手的最终归档成绩、排名和奖项。模块级成绩由 assessments APP 管理，不在 competitions 前台录入。

## 6. 常见问题

### 6.1 为什么前台不能修改赛事、项目、模块等信息？

因为这些属于主干数据，由后台统一维护。前台只负责补录当前届次的业务数据。

### 6.2 为什么我能看到竞赛页面，但看不到新增入口？

因为查看权限和新增权限是分开的。只有拥有对应 add 权限时，菜单和录入页面才会显示。

### 6.3 标准模块和本届官方模块有什么区别？

标准模块用于长期复用和跨 APP 引用；本届官方模块用于记录某一届比赛实际公布的模块口径，两者之间通过映射关系关联。

### 6.4 模块主线和标准模块是什么关系？

模块主线是更稳定的长期分析口径；标准模块是某一版标准体系下的具体实现。一个标准模块通常会映射到某条主线，但不同版本的标准模块可以共用同一条主线。

### 6.5 如果我分不清“竞赛项目、模块主线、标准模块、本届官方模块”，应该看哪里？

建议直接阅读 [glossary.md](glossary.md)，这里集中解释了 competitions 中最容易混淆的术语。
