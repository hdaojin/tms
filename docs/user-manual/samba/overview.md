# samba APP 总览

## 1. 功能概述

samba 模块用于为已登录用户提交 Samba 账户开通和密码修改请求。

当前页面改为后台任务模式：

- 页面提交后，请求会进入 Samba 操作队列。
- 队列需要管理员运行或配置 `uv run manage.py process_samba_operations` 后台命令来消费。
- 当前页面不会同步等待系统命令执行完成。
- 页面顶部会显示最近一次任务的状态与结果摘要，便于自行确认是否成功。

## 2. 适用角色

本页面面向需要访问 Samba 共享文件夹的普通登录用户。

如果任务长时间停留在“待处理”或“处理中”，需要联系系统管理员排查后台命令或服务。

管理员需要保证队列消费命令持续或定时运行，例如通过系统服务、计划任务或进程管理工具执行：

```bash
uv run manage.py process_samba_operations
```

## 3. 入口路径

前台入口：

- `/samba/accounts/`

菜单入口：

- 顶部或侧边导航中的“开通Samba账户”
- 子菜单“SMB账户”

## 4. 常见任务

### 4.1 提交 Samba 账户开通任务

步骤：

1. 进入 Samba 账户页面。
2. 输入两次相同的新密码。
3. 点击“提交开通任务”。

结果：

- 请求会写入操作队列，等待后台命令创建或校验本地用户、所属组和 Samba 账户。
- 如果账号此前已存在，系统会按幂等方式更新密码和组信息。
- 页面顶部会出现最近一次后台任务的状态。

### 4.2 提交 Samba 密码修改任务

前提：

- 页面显示“最近一次已知状态为已开通”。

步骤：

1. 输入两次相同的新密码。
2. 点击“修改密码”。

结果：

- 请求会写入操作队列，等待后台命令修改 Samba 密码。
- 提交完成后页面会提示“请求已提交”，实际结果以最近任务状态为准。

## 5. 状态说明

页面顶部的“最近一次后台任务”会显示以下状态：

- 待处理：请求已提交，还没有开始执行。
- 处理中：后台正在执行系统命令。
- 已完成：最近一次任务已成功完成。
- 失败：后台任务执行失败，页面会显示错误摘要。

如果“处理中”的任务超过系统配置的超时时间，后台命令会将其标记为失败并清空加密载荷。失败后用户可以重新提交任务。

“当前状态”显示的是系统最近一次已知状态：

- 最近一次已知状态为已开通：说明最近一次成功任务表明 Samba 账户可用。
- 最近一次已知状态为未开通：说明最近一次成功任务表明账户未开通或已停用。
- 尚未确认：系统还没有保存过可用的历史状态，首次使用时可以直接提交开通任务。

## 6. 使用提醒

1. 两次输入的密码必须一致，并满足本站密码策略。
2. 提交任务后可以直接刷新页面查看状态，无需反复重复提交。
3. 如果页面提示已有正在处理的 Samba 操作，请等待当前任务结束后再试。

## 7. 常见问题

### 7.1 为什么提交后没有立刻提示“开通成功”？

因为系统改为后台任务模式，页面只负责接收请求，不会同步等待服务器命令执行完成。

### 7.2 页面显示“尚未确认”，但我记得以前开通过怎么办？

可以直接再次提交“开通任务”。系统会按幂等逻辑校验现有账户，并更新密码和组信息。

### 7.3 页面一直显示“待处理”怎么办？

这通常表示后台处理进程没有及时消费任务，需要联系管理员检查 Samba 后台任务处理命令或服务状态。

### 7.4 页面显示“执行超时”怎么办？

说明上一次后台任务已经被系统标记为失败。请先联系管理员确认后台命令运行正常，再重新提交开通或改密请求。
