# accounts APP 总览

## 1. 适用对象

本手册适用于负责后台用户、用户组和权限授权的管理员。

典型角色包括：

- 超级管理员
- 负责维护用户组与权限模板的系统管理员
- 需要为单个用户追加特殊权限的授权管理员

## 2. 页面入口

后台入口位于 Django Admin：

- `/admin/auth/group/`：维护用户组、组说明、业务权限包与额外原生权限
- `/admin/auth/user/`：维护用户基本信息、所属用户组、业务权限包与额外原生权限

前台只读入口位于侧边栏“账户 / 用户管理”：

- “用户列表”：查看系统内全部用户的姓名、角色、性别、联系方式、宿舍、入读日期、离开日期、激活状态，并可进入用户详情。
- “角色列表”：查看角色名称、英文标识、描述、用户数和业务权限包。

以上两个前台入口需要“查看全部用户资料”权限。
“用户列表”默认先按账号是否有效排序，有效账号在前、无效账号在后；同一状态内按入读日期倒序排列，没有入读日期的账号排在有入读日期的账号之后；最后用账号主键倒序兜底，保证顺序稳定。

推荐操作顺序：

1. 先在“用户组”里配置通用权限。
2. 再在“用户”里做个别补充。
3. 只有业务权限包覆盖不到的场景，才手工勾选额外原生权限。

## 3. 授权方式

后台授权现在分成两层：

### 3.1 业务权限包

作用：

- 用业务语言授权，而不是手工逐个勾选底层 Django 权限。
- 勾选后系统会自动补齐该业务能力所需的底层权限。

当前已提供的典型业务权限包包括：

- 查看全部用户资料
- 查看全部考核成绩
- 录入奖惩记录
- 审核奖惩记录
- 查看全部奖惩记录
- 发布通知
- 上传会议记录
- 删除会议记录
- 关联代表队
- 新增选手
- 新增专家
- 新增岗位人员
- 录入竞赛总成绩
- 上传训练日志
- 查看教练训练日志
- 查看选手训练日志
- 查看全部训练日志

例如：

- 勾选“查看全部用户资料”后，系统会自动授予用户列表、用户详情页和角色列表所需的底层权限。
- 勾选“发布通知”后，系统会自动授予通知发布所需的底层权限。
- 勾选“录入奖惩记录”后，系统会自动补齐奖惩记录新增、记录列表查看、奖惩汇总查看等底层权限，减少漏配。
- 勾选“上传会议记录”后，系统会自动授予会议记录上传所需的底层权限。
- 勾选“删除会议记录”后，系统会自动授予会议记录删除所需的底层权限。
- 勾选“录入竞赛总成绩”后，系统会自动授予竞赛总成绩录入所需的底层权限。

### 3.2 额外原生权限

作用：

- 处理业务权限包之外的特殊授权。
- 只在确有需要时使用。

使用建议：

- 常规授权优先使用业务权限包。
- 只有需要临时、细粒度、非模板化授权时，再勾选额外原生权限。

## 4. 常见任务

### 4.1 给一个用户组配置“录入奖惩记录”能力

步骤：

1. 进入“用户组”列表。
2. 打开目标用户组。
3. 在“业务权限包”里勾选“录入奖惩记录”。
4. 保存。

结果：

- 该组会自动获得录入奖惩记录所需的底层权限。
- 后续新加入该组的用户会继承这组权限。

### 4.2 给单个用户追加特殊权限

步骤：

1. 进入“用户”列表。
2. 打开目标用户。
3. 先确认其所属用户组是否已经覆盖主要权限。
4. 如仍需特殊授权，再在“额外原生权限”里补充。
5. 保存。

结果：

- 用户会保留组继承权限。
- 额外原生权限只对该用户本人生效。

### 4.3 查看用户与角色

步骤：

1. 打开侧边栏“账户 / 用户管理”。
2. 进入“用户列表”，查看全部用户及其所属角色；无角色用户会显示“未分配”。
3. 进入“角色列表”，查看每个角色的英文标识、描述、用户数和业务权限包。

说明：

- “角色”包含 Django 用户组，以及账号的“工作人员”“超级用户”系统身份；超级用户不重复显示工作人员身份，不同角色会用 soft 风格的彩色标签区分，用户列表和用户详情保持一致。
- “英文标识”和“描述”来自用户组扩展信息。
- “业务权限包”显示管理员在后台为该角色配置的业务化授权名称。
- “激活”显示账号是否有效；绿色圆形勾表示有效账号，红色圆形叉表示无效账号。
- 用户列表中只有“姓名”“角色”“性别”“出生日期”“入读日期”“离开日期”“激活”列可点按排序。
- 如果管理员将已有账号从有效改为无效，且该用户资料没有填写“离开日期”，系统会自动把失效当天写入“离开日期”；已填写的离开日期不会被覆盖。

## 5. 使用提醒

1. 用户组授权优先于单用户散权，便于后续维护。
2. “业务权限包”是推荐入口，“额外原生权限”是高级兜底入口。
3. 如果一个业务能力已经有权限包，不建议再手工逐条勾选同一批底层权限。
4. 组里的业务权限包与用户自己的业务权限包会分别生效，互不覆盖。

## 6. 常见问题

### 6.1 为什么我已经勾选了业务权限包，还会看到“额外原生权限”区域？

因为系统仍然保留 Django 原生权限方式，方便处理特殊场景；但常规情况下不需要再手工去勾业务权限包已经覆盖的权限。

### 6.2 应该优先给组授权还是给用户授权？

优先给组授权。只有当某个用户需要个别例外权限时，才建议直接给用户追加额外原生权限。

### 6.3 业务权限包会不会覆盖我手工加的权限？

不会。业务权限包会自动补齐它自己的依赖权限；你手工勾选的额外原生权限会继续保留。
