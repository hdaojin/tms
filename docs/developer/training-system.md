# 网络系统管理项目训练体系结构设计思路（讨论草稿）

- 职业标准：世界技能大赛认为选手“应当具备什么”；
- 能力模型：我们将职业标准转化为可训练、可观察、可评价的能力结构；
- 竞赛评价模型：历届试题和评分方案“实际考了什么、如何给分”；
- 训练运行体系：如何通过计划、任务、资源、日志和测评提升选手；
- 训练档案：上述过程产生的文件、数据和证据。


## 建议采用“一条主线、三套模型、两个闭环”

### 1. 一条主线：选手能力发展

整个体系的核心不是“管理训练资料”，也不是“统计训练次数”，而是：

> 持续识别目标能力、测量选手当前能力、发现能力差距，并通过训练缩小差距。

可以概括为：

职业标准与竞赛要求
        ↓
目标能力模型
        ↓
选手当前能力画像
        ↓
能力差距
        ↓
训练计划与训练任务
        ↓
训练执行与过程证据
        ↓
测评与诊断
        ↓
更新能力画像和训练计划


### 2. 三套模型

#### 第一套：职业能力模型

回答：

> 网络系统管理选手究竟应该具备哪些能力？

来源包括：

- WSOS；
- 行业职业能力要求；
- 当前竞赛技术发展方向；
- 历届竞赛长期稳定出现的能力；
- 专家经验。

它应当是相对稳定、可以版本化的“基座”。


#### 第二套：竞赛评价模型

回答：

> 某一届比赛具体考了什么，通过什么证据给分？


来源包括：

- Test Project；
- Marking Scheme；
- Mark Summary Form；
- 评分脚本；
- 选手得分表；
- 裁判观察和赛后复盘。

它随赛事变化，不应直接等同于职业能力模型。


#### 第三套：训练发展模型

回答：

> 如何把一个选手从当前水平训练到目标水平？

包括：

- 训练周期；
- 阶段目标；
- 周训练计划；
- 日训练任务；
- 训练资源；
- 训练执行记录；
- 问题跟踪；
- 阶段测评；
- 选手能力画像；
- 计划调整。

### 3. 两个闭环

#### 快闭环：选手训练闭环

以周为主要控制单位：

制定周计划

→ 执行训练任务   
→ 记录完成情况和问题  
→ 周测或过程评价  
→ 更新个人能力画像  
→ 调整下一周计划  

这个闭环可能每天、每周运行。

#### 慢闭环：训练体系演进闭环

以一次重大考核或一个竞赛周期为单位：

新TD、TP、评分方案和比赛结果  
→ 提取新证据  
→ 分析能力覆盖和技术变化  
→ 提出能力模型调整建议  
→ 专家审核  
→ 发布新的能力模型版本  

正式比赛的结果不应直接修改技能树，而应先进入证据库，经过分析和审核后再形成新版本。  

## 能力、技能、知识应当如何区分

能力是选手在具体情境和约束下，综合运用知识、技能和职业行为完成工作任务的表现。

技能是完成能力所使用的方法和操作。

知识是支撑判断和操作的原理。


能力领域
  └─ 能力主题
      └─ 能力单元
          ├─ 知识要素
          ├─ 技能要素
          ├─ 职业行为
          └─ 可观察的评价证据


模块
└─ 能力领域
   └─ 能力主题
      └─ 能力单元
         ├─ 知识要素
         ├─ 操作技能
         ├─ 自动化技能
         ├─ 验证方法
         ├─ 故障排除
         ├─ 训练任务
         └─ 评价证据

例如：

A Linux
└─ 网络服务
   └─ DNS服务
      └─ 部署权威DNS服务
         ├─ 理解权威解析和区域文件
         ├─ 安装BIND
         ├─ 创建正向和反向区域
         ├─ 设置权限和安全控制
         ├─ 使用dig验证
         ├─ 使用脚本或Ansible部署
         └─ 诊断常见故障

## 建议最终形成的训练体系框架

可以将整个世界技能大赛网络系统管理项目训练体系正式定义为六个子体系。

1. 职业能力标准体系
- WSOS版本；
- 能力领域；
- 能力主题；
- 能力单元；
- 知识、技能和职业行为要素；
- 能力之间的前置、依赖和关联关系。
2. 竞赛研究与评价证据体系
- 历届TD；
- Test Project；
- Marking Scheme；
- 评分点；
- 分值；
- 评分脚本；
- 历届得分；
- 考点与能力映射；
- 趋势和频率分析。
3. 训练目标与计划体系
- 竞赛周期目标；
- 阶段目标；
- 选手个人目标；
- 能力优先级；
- 周计划；
- 日训练任务；
- 阶段关卡和计划调整规则。
4. 训练内容与资源体系
- 标准训练任务；
- 综合训练项目；
- 故障案例；
- 模拟试题；
- 教学讲义；
- 操作指南；
- 环境模板；
- 自动化和评分工具；
- 参考答案。
5. 训练执行与问题管理体系
- 任务分配；
- 训练执行；
- 训练日志；
- 成果证据；
- 问题记录；
- 原因分析；
- 解决措施；
- 周复盘；
- 训练进度。
6. 测评诊断与选手发展体系
- 基线诊断；
- 过程测评；
- 阶段考核；
- 模拟赛；
- 交流赛；
- 选拔赛；
- 正式比赛；
- 评分点得分；
- 能力画像；
- 差距分析；
- 稳定性与趋势；
- 后续训练建议。

## 最重要的五个结论

第一，整个体系应以“能力模型”为基座，而不是以知识点目录为基座。

第二，WSOS、竞赛考点和训练内容是三套不同结构，必须通过映射关联，不能直接合并。

第三，评分方案是量化考点的主来源，但必须结合试题理解任务情境、约束和隐含能力。

第四，训练闭环的核心不是日志归档，而是“能力差距—训练任务—表现证据—能力画像—计划调整”。

第五，技能树只是能力模型的一种展示视图；正式比赛首先更新竞赛证据和训练优先级，经过审核后才更新能力模型版本。
