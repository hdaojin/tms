# ADR 0006：领域独立技能树版本与训练周期版本快照

- 状态：已接受
- 日期：2026-08-21

## 背景

原有 SkillTreeVersion 属于整个 SkillProject，节点再分别记录 TechnicalDomain。这迫使同项目不同领域共享版本节奏，也使单棵树同时承担多个领域结构。TrainingCycle 只能固定一个项目级版本，无法准确表达各领域训练时实际采用的标准快照。

WSOS 已有版本、章节和技能映射模型，但维护入口只覆盖版本外壳，章节与映射缺少完整业务页面。

## 决策

1. SkillTreeVersion 归属于一个 TechnicalDomain；SkillTreeNode 不再持久化 technical_domain，其领域由版本唯一确定。每个领域至多有一个 current 版本。
2. 新版本可以基于同领域当前版本、任意历史版本或空白结构创建。`based_on` 创建后不可更改；克隆只复制节点结构和顺序，继续引用相同的稳定 Skill。新版本默认不是 current，切换 current 是单独动作。
3. 单个技能树内不允许跨领域或跨版本移动。一个 Skill 只要其主要或关联领域允许，仍可分别出现在多个领域的不同版本中。
4. TrainingCycle 通过 TrainingCycleSkillTreeVersion 固定一个或多个“领域 + 版本”快照，同一领域最多一个版本且至少选择一个领域。TrainingTask 的领域只能来自其周期快照。
5. 周期快照仅在 PLANNING 且没有已开始执行时可编辑；已经被任务使用的领域不能移除。周期状态只允许依次进入 ACTIVE、COMPLETED、ARCHIVED，不能回退。
6. 阶段周期只能选择父周期已经包含的领域，但允许为这些领域选择不同版本；父周期选择只作为新建时的初始值，保存后彼此独立。
7. WSOS 保持 SkillProject 级标准轴，粒度止于 WSOSSection。Skill 与 Section 多对多映射并可记录备注；TechnicalDomain 只作为技能候选搜索过滤条件，不成为 WSOS 归属。
8. URL 直接切换到领域版本语义，不保留旧项目级或节点领域参数路由及重定向。

## 数据迁移

采用前向分阶段迁移。每个旧项目级版本按项目全部技术领域拆分；按 `order, pk` 排序的第一个领域复用旧版本主键，其余领域创建等价版本。节点按旧 technical_domain 迁入对应领域版本，即使某领域没有节点也创建版本。旧 TrainingCycle 为每个拆分后的领域版本建立快照。若旧版本所属项目没有技术领域，迁移明确失败，不静默丢弃数据。

## 后果

各技术领域可以独立换版，训练周期保留可审计的多领域标准快照。历史结构仍引用稳定 Skill，因此修改 Skill 长期属性会继续反映到所有版本；版本不是 Skill 属性快照。调用方必须从领域上下文创建版本，并使用新的硬切换 URL。
