# ADR 0010：计划内排班、任务与历史调整

- 状态：已接受
- 日期：2026-10-31

2026-11-01：统一发布、任务保存即发布及过期锁定的规则已由 [ADR 0011](0011-training-publication-and-retrospective-changes.md) 替代；下文保留原决策背景。

训练计划先确定每日值班和四时段排班，统一发布后再由主要教练填写多个独立任务。采用“计划 → 每日安排 → 时段排班 → 任务 → 执行”，而非把排班、人员和多任务混在同一任务表中；日期框架用于人工录入，不代表自动排班。任务保留原主键及执行／日志关联，无时段的旧任务保留历史身份。

发布后的排班变更以成组申请记录原因和原始版本，审批时在事务内重新校验权限、版本及执行状态，整体批准或驳回。允许具有指定计划审批权限的人自批，避免制造额外的管理员旁路；自批同样保留申请和审批记录。Django Permission 与计划内显式职责共同授权，不使用角色名称或同领域权限推导新时段任务的编辑权。后台工作流对象只读，所有正式写入通过前台事务服务完成。

按 2026-10-31 本次重构确认，锁定依据改为计划创建时固化的时段结束时间，边界为 `now >= ends_at`。执行开始不提前锁定；达到结束时间后禁止修改排班、领域、教练、任务定义及任务分配，也禁止人员交接申请和批准。执行状态、进度及反馈仍可继续写入。保留用户明确确认的技能关联修正例外：技能可选，执行后、锁定后及归档后均可独立修正并留痕。

“全体负责教练”“全体值班教练”固定为排班发布时的周期教练名单。任务保存即生效，默认分配任务创建时的计划参与选手。现行 Excel 导入规则以导入预览时的当前参与选手为准，确认时复核名单，任务保存为草稿。成员变化不自动改写历史分配；撤销仅允许未开始且无进度者，并保留原因、操作人及时间。

任务定义维护范围收紧为超级管理员、当前主要教练；全体负责时另允许排班人员，不延续任务管理员代填旁路。选手只读本人有效分配任务，内部历史及审批不可见。自主任务由本人维护，同计划中曾负责其官方任务的教练可读可反馈，历史负责关系独立保存。

进度、进度修订、状态变化及多教练反馈分别记录，附件与各自业务对象关联。审计记录由 training 拥有，不可覆盖，不替代数据库外部操作的完整审计系统。新增数据使用兼容迁移保留旧主键、文件路径和日志引用；不从当前配置或成员名单伪造旧时间快照与创建名单。
