# ADR 0009：明确业务授权与默认角色

- 状态：已接受
- 日期：2026-10-28

## 决策

1. 登录只提供身份，不隐含业务能力。功能面板、本人资料查看与维护、登录退出、注册及密码操作属于基础账户能力；本人资料锁定后只读，管理员解锁，不能借此操作他人资料。关于页面和倒计时保持明确公开。反馈入口、查询和写入服务执行明确的查看、提交、回复和附件权限，另叠加私密、匿名及关闭状态规则。
2. 沿用 ADR 0003 与 0007：Group 承载角色，权限包仍是 APP 内小能力，Django Permission 是运行时事实。同一组同时提供领域权限和范围，不能跨组拼接；不新增 Role 模型或班级范围。
3. `accounts.bootstrap.DEFAULT_ROLES` 声明选手、教练、班务组合；`core.role_bootstrap` 承担预检、差异与应用，纳入 Bootstrap 主事务。codename 仅作初始化稳定定位，不参与运行时授权。普通模式只补缺失角色；force 恢复声明字段与权限包并保留成员、领域、额外权限。不凭名称合并，不自动设置注册默认组。
4. 默认教练不配置领域，可复制成各领域的独立组。标准可跨领域读，按领域维护；版本和 WSOS 治理仍限 superuser。全局训练统筹、全体日志、删除与导出另授，业务成员关系不从角色推导。
5. 原全局竞赛权限包保留编码和语义，明确标注全系统范围；另提供按既有对象规则维护的日常包，不包含新增竞赛与考核，由管理员统一创建。目录治理与全局扩大权不进入默认领域教练组合。
6. 前端角色编辑、复制、成员/领域分配及他人权限诊断限超级管理员；个人直授仍在后台维护。保存先预览，签名绑定配置与现状，过期或变更后重新预览；写入复用事务授权服务。
7. 用户列表和详情提供用户侧多角色分配，仍仅限超级管理员。预览绑定用户现有授权和新旧角色配置，事务中锁定相关组及用户后校验；只保存组成员关系，保留个人直授与账号标志，不推导训练身份。
8. 用户列表批量启停、追加/移除角色和维护离开日期，详情单人启停与日期维护，均仅限有效超级管理员。全匹配选择在预览时固定名单，签名绑定操作人、目标与相关现状，事务确认时重新检查；整批成功或整批拒绝。前端不得停用超级管理员或批量增减其角色。管理员可单独维护锁定资料的离开日期，其他锁定字段不开放；前端和后台的账号激活状态与离开日期完全独立，停用不再自动补日期，不改动历史日期。

9. 用户详情的完整资料和邮箱编辑、保存并锁定及单独解锁仅限有效超级管理员，查看权限不提供写权限。管理员须先解锁再编辑，解锁不保存其他字段，解锁后本人可重新维护资料；独立离开日期入口的锁定例外保留。本人和管理员资料写入复用事务服务，锁定确认提交完整主表单，普通保存采用现有表单校验。

## 升级要求

不清空、不自动迁移现有组、成员或个人授权。上线前按授权手册预览反馈入口收紧的影响，管理员显式为需要继续使用反馈的账号或组补授查看、提交、回复权限。权限包展开变化需执行现有 `reconcile_permission_assignments --dry-run`，确认后显式 `--apply`；正常升级不反复运行 Bootstrap。权限迁移、成员分配和生产部署分别确认执行。

## 验证

无授权账号的直接 URL、POST 和附件均被拒绝；权限与受众叠加；初始化幂等、冲突、过期预览和事务回滚有测试；保留同组领域约束和既有私密性规则。默认角色、可选能力和前端流程见 `docs/user-manual/accounts/overview.md`。
