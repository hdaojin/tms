## 1. 目标与范围

将训练计划重构为一个统一的训练安排与执行管理功能：

-   训练计划由教练/管理人员制定；选手不创建个人训练计划。
-   训练任务是训练计划的组成内容，不再设置独立的训练任务一级菜单。
-   训练计划详情页同时提供日程排班视图和训练任务列表。
-   教练安排官方任务；选手可以在官方任务之外添加个人自主任务。
-   记录选手的任务状态、训练进度、附件和教练反馈，为未来训练日志、技能掌握分析、个体/群体训练分析及下一周期计划优化积累结构化数据。
-   支持基于用户提供的原 Excel 模板导入、导出训练计划。

### 本阶段不做

-   不开发完整训练日志 APP 或自动生成训练日志。
-   不开发完整技能树分析、技能掌握度分析或训练分析仪表盘；只做好数据关联和结构化存储基础。
-   不做计划延期、缩短、复杂计划版本管理、跨周期未完成任务自动迁移。
-   不建立"选手个人训练计划"实体或计划级接受/确认流程。
-   不将选手自主任务纳入官方训练计划完成率。
-   不强制训练任务关联技能；技能关联仅预留可选能力。

## 2. 业务核心概念

### 2.1 训练计划

-   计划由管理员/教练创建，创建时指定排班人员、计划周期和参与选手。
-   周期为固定周期，例如按周、按月或指定起止日期；创建后不提供延期或缩短操作。
-   下一个训练周期创建新的计划；本阶段不做计划间自动任务迁移。
-   计划详情页是官方排班、任务编制和执行信息的统一入口。

### 2.2 计划日期与四个时段

每个计划日期自动生成四个时段，不需要用户点击"补齐日期框架"：

1.  早读
2.  上午
3.  下午
4.  晚上

四个时段的开始、结束时间由系统统一配置。创建计划时，将当时的四个时段时间配置快照保存到计划/时段数据中，后续系统配置调整不得改变既有计划的锁定时间。

时间配置的具体数值由系统管理员配置；不要把讨论中举例的时间误当成已确认的固定值。

每个时段最多设置一个训练领域；该时段内可以有多个独立训练任务。值班教练和日备注按日期管理。允许设置休息日/不安排训练。

### 2.3 教练安排的官方任务

-   任务必须属于某计划的某个日期时段。
-   一个时段限定一个训练领域，该时段内所有任务继承该领域。
-   一个时段可有多个独立任务。
-   新增任务采用轻量弹窗/局部表单：任务标题必填；Markdown
    说明、附件、技能关联等为可选扩展，避免填写负担。
-   训练任务不强制关联技能；技能树尚未完善时可以不关联，保留未来关联能力。
-   教练任务附件与选手进度附件分开管理、分开授权。
-   训练任务内容保存后立即生效，不需要管理员审批；任务修改必须留痕。

### 2.4 负责教练与主要教练

-   一个时段可指定多个负责教练。
-   多位负责教练时必须指定一名主要教练；主要教练必须属于该时段负责教练集合。
-   只有一名负责教练时，该教练默认为主要教练。
-   "全体"是负责教练选择器中的特殊选项，与具体教练名单互斥，不能同时选择。
-   负责教练选择"全体"时，由管理员或排班人员负责填写该时段训练任务。
-   主要教练负责该时段官方训练任务的创建、编辑和删除/清空。
-   主要教练发生经审批的变更后，新主要教练接管现有任务的后续编辑和删除权限；原任务创建者身份及历史记录保持不变。
-   当前负责教练可以对分配给选手的官方任务提供独立文字反馈；多位教练的反馈互不覆盖。

### 2.5 选手分配

-   创建官方训练任务时，默认分配给创建时该计划内的全部选手。
-   也可以指定部分选手；人员选择交互优先复用会议 APP
    的人员选择组件/模式。
-   创建任务时固化当时的选手分配快照。之后新加入计划的选手不会自动获得历史任务，教练可以主动补充分配。
-   选手退出计划不自动删除其已有任务分配和执行历史。
-   时段锁定前，当前主要教练可增加任务分配。
-   时段锁定前，仅当某选手任务分配尚未开始且没有任何进度记录时，才允许撤销该分配；撤销采用逻辑撤销，记录操作人、时间和原因。
-   时段锁定后，不得增删或调整任务分配。

## 3. 页面与交互

### 3.1 训练计划详情页

训练任务不再单独占据一级菜单。计划详情页至少提供：

-   **日程视图**：按日期展示每日四个时段。
-   **任务列表**：当前计划全部官方训练任务的通用列表，支持搜索、筛选、排序和分页。

任务列表复用项目现有表格组件/模板和统一过滤行样式，视觉风格与
`/meetings/`、`/accounts/users/` 保持一致。

### 3.2 日程视图

-   一天一行，四个时段横向展示。
-   日期显示星期；可以在日期单元格中组合显示日期和星期，避免不必要的列。
-   不显示原先的"类型"列。
-   不设置独立"操作"列，保留"备注"列。
-   分页每页固定 31 个日期（计划不足 31 天时按实际日期显示）。
-   日期支持勾选、全选和清空选择；交互参考用户列表。
-   计划创建后按起止日期自动生成所有日期行和四个时段，不再提供"补齐日期框架"按钮。
-   时段单元格采用已确认的状态驱动交互：根据当前计划阶段、时段是否锁定、当前用户角色及该时段是否有排班/任务，决定点击后可执行的操作。
-   优先行内编辑；多教练选择等复杂控件可采用紧凑弹层/小弹窗。不得将日程编辑做成需要离开列表的大型独立表单。
-   排班与任务保存采用 HTMX 局部更新，不无必要地刷新整页。

### 3.3 排班阶段与清空

-   创建计划时必须指定排班人员。
-   排班阶段由排班人员完成日期时段、训练领域、负责教练、主要教练和值班教练安排。
-   排班阶段允许纠错和清空重排；清空功能仅在排班阶段开放。
-   排班定稿后，不再允许通过普通"清空排班"功能重置。
-   排班定稿后，负责教练只能清空/管理自己负责范围内的任务内容；不得借此清空排班信息。清空任务内容必须保留审计记录，并受时段自动锁定约束。
-   排班定稿后，如需更换负责教练、主要教练、值班教练或调整排班，应走管理员审批流程；审批通过后才生效。
-   已锁定时段不接受任何排班调整申请或导入覆盖。

### 3.4 任务列表与新增

-   任务列表按任务粒度展示，一条独立任务一条记录。
-   支持搜索、筛选、排序；至少支持日期、时段、训练领域、负责/主要教练、任务标题等筛选维度。
-   任务新增入口放在计划详情页对应时段中，不提供独立任务菜单。
-   新增任务默认只要求填写标题；Markdown
    说明、附件、技能关联和选手范围作为可选扩展。
-   同一时段可添加多项独立任务。
-   任务保存后立即生效。
-   任务修改、删除/清空均保留前后内容和操作历史。

## 4. 计划阶段、权限与历史

### 4.1 计划阶段

至少区分：

1.  **排班阶段**：排班人员安排每日时段。
2.  **任务编制/执行阶段**：主要教练编制任务，选手执行并记录进度；任务编制与训练执行可以并行发生。
3.  **结束/归档状态**：计划周期结束后作为历史计划查询。不要引入复杂版本体系。

### 4.2 排班权限

-   排班阶段：指定排班人员负责排班。
-   排班定稿后：排班调整需管理员审批。
-   时段锁定后：排班字段禁止修改。
-   负责教练为"全体"时，任务由管理员或排班人员编制。

### 4.3 任务权限

-   管理员：具有管理权限，可查看完整历史。
-   当前主要教练：可以创建、编辑、删除自己负责时段的任务，并查看这些任务的完整历史。
-   其他负责教练：可以查看任务及历史，但不能修改任务定义；可以提交自己的教练反馈。
-   选手：只能看到当前有效且分配给自己的官方任务内容，不展示内部管理信息、审批信息和任务修改历史。
-   主要教练变更后，新主要教练接管任务编辑/删除权限；原创建者信息不改写。
-   删除使用软删除/取消状态，保留任务原内容、删除人、时间和原因；不能物理删除已经产生执行数据的任务。

### 4.4 历史记录可见性

-   管理员：完整修改历史。
-   当前主要教练：其负责任务的完整修改历史。
-   其他负责教练：可查看历史，但不能修改。
-   选手：只看当前有效任务，不显示内部修改历史。
-   任务历史至少记录操作类型、操作人、时间、修改对象、修改前后内容、审批信息（如适用）和原因（如适用）。

## 5. 时段自动锁定

这是高优先级业务规则，必须在所有写入入口统一执行。

-   系统统一配置早读、上午、下午、晚上四个时段的开始和结束时间。
-   创建计划时保存时段时间快照。
-   当服务器当前时区时间达到或超过该时段快照的结束时间时，该时段自动进入"已执行/已锁定"状态。
-   不要求教练手动确认，也不依赖后台定时任务及时运行；可根据当前时间实时计算锁定状态。
-   后端每个写操作必须重新校验，不能只在前端禁用按钮。
-   锁定后禁止修改：时段排班、训练领域、负责教练、主要教练、值班教练、任务定义、任务增删、任务选手分配。
-   锁定后仍允许：选手更新自己的任务状态、补充训练进度记录，教练追加文字反馈；这些属于执行事实，不属于计划/任务定义修改。
-   使用 Django timezone-aware
    时间处理，并遵循项目配置的时区。边界条件按 `now >= slot_end_at`
    锁定。

## 6. 选手任务执行、进度与反馈

### 6.1 官方任务完成状态

每个"选手---官方任务"分配记录独立维护状态：

-   未开始
-   进行中
-   已完成
-   未完成

定义： - 进行中：训练仍在持续。 -
未完成：本次训练结束，但仍有未完成部分。

状态属于选手任务分配/执行记录，不属于公共任务定义。不同选手互不影响。

选手可以在标记已完成后再次修改状态（例如误操作或发现遗漏）。每次状态变化均记录操作人、时间、变更前状态和变更后状态。时段锁定不禁止选手更新自己的执行状态。

### 6.2 训练进度记录

-   选手可以针对分配给自己的任务多次提交进度。
-   每次提交形成独立、按时间排序的进度记录，不覆盖之前记录。
-   记录至少包括：
    -   已完成的部分/已掌握的知识点；
    -   未完成的部分/存在的问题。
-   支持 Markdown。
-   支持上传图片和附件。
-   允许对既有进度记录进行修订，但修订必须保留原始版本和修改历史。
-   "进行中"或"未完成"时应明显引导选手填写相应进度；不要把简单状态更新变成繁重的必填表单。
-   进度记录是可查询、统计、追溯的核心业务数据，不只是训练日志附件。

### 6.3 教练反馈

-   官方任务：当前时段所有负责教练均可对分配给选手的任务填写文字反馈（方案
    B）。
-   每条反馈独立保存作者、时间和内容，不覆盖其他教练的反馈。
-   选手可以查看针对自己的教练反馈。
-   反馈不是复杂评分，不引入成果打分体系。

### 6.4 附件边界

-   **教练任务附件**：教练发布任务时上传，供被分配该任务的选手和有权教练查看/下载。
-   **选手进度附件**：选手在进度记录中上传，供该选手及对应负责教练查看。
-   两类附件分别关联各自业务对象，权限隔离，不混用字段或附件集合。
-   复用 TMS
    现有文件存储和权限机制；敏感附件遵循项目既有私有媒体访问方式。

## 7. 选手自主训练任务

### 7.1 定位

-   不建立个人训练计划。
-   选手查看自己当日训练任务时，可以在教练官方任务基础上添加个人自主任务。
-   官方计划始终由教练制定；个人任务不改变官方排班、官方任务或其他选手的数据。

### 7.2 个人任务字段与时间

-   日期必选，必须处于当前计划周期内。
-   时段可选：早读、上午、下午、晚上；也可以不指定时段。
-   允许在休息日添加个人任务，不受教练当天排班状态限制。
-   任务标题必填；任务说明可选，支持 Markdown。
-   训练领域可选。
-   技能关联预留为可选，不强制选择。
-   个人任务可以有自己的完成状态和进度记录；纳入统一训练过程数据体系，但与官方任务分开统计。

### 7.3 个人任务权限

-   任务所属选手：查看、编辑、删除自己的个人任务，并更新状态、提交进度。
-   该选手对应的负责教练：可以查看个人任务并提供文字指导反馈；不能编辑或删除选手个人任务。
-   其他项目教练和其他选手：不可查看。
-   管理员：按系统管理权限查看和管理。
-   教练反馈独立记录作者和时间，不覆盖历史。

## 8. 选手可见的日程

-   选手可以查看整个训练计划的日期和四时段日程框架。
-   选手只能看到分配给自己的官方任务内容；不得看到未分配给自己的任务标题、说明、附件或其他选手的进度。
-   对未分配给自己的时段，可显示必要的日程信息或"有其他训练安排"，但不得泄露任务内容。
-   选手可以在当天视图中同时看到自己的官方任务和个人自主任务，并清楚区分来源：
    -   "教练安排"
    -   "自主添加"

## 9. 数据统计口径与未来扩展

### 9.1 两类任务分开统计

教练安排任务和选手自主任务在数据模型、权限和统计口径上明确区分，但都纳入统一训练过程数据体系。

-   官方训练计划完成率只统计教练安排任务。
-   个人自主任务单独统计，不影响官方完成率。
-   两类任务都可作为未来训练日志、技能掌握分析和训练计划优化的数据来源。

### 9.2 官方完成率

-   统计单位为"选手---官方任务"分配记录。
-   只统计时段结束、已经到执行时间的有效分配记录。
-   已撤销的分配不计入分母；已经有进度记录的分配不得撤销。
-   完成率 = 已完成的有效官方任务分配数 /
    已到执行时间的有效官方任务分配总数。
-   未开始、进行中、未完成均计入分母但不计入已完成数。
-   不将个人自主任务混入官方完成率。

### 9.3 数据可分析性

结构化保存计划、时段、领域、任务、任务来源、选手分配、状态、状态历史、进度记录、教练反馈和附件关联。未来可据此分析单个选手、选手群体、共性问题和训练计划调整依据。本阶段不实现完整分析界面。

## 10. Excel 导入/导出

### 10.1 唯一模板

以用户提供的文件：

`2026.10-世界技能大赛网络系统管理项目10月份训练计划.xlsx`

为格式基准。

-   只处理名为"训练计划"的工作表。
-   "班级课表"工作表完全忽略，不导入、不导出。
-   保留原"训练计划"工作表的八列结构、列顺序、原有样式、字体、边框、颜色、列宽、标题和合并单元格布局。
-   不擅自增加列、增加数据工作表或重新设计模板。
-   原模板每天为三行；导出时每天增加一行"早读"，使用原有时段行的样式，形成早读、上午、下午、晚上四行。
-   日期、星期、值班教练和备注继续按天合并；时段、领域、训练任务、负责教练按时段行表达。
-   不修改用户提供的源文件；导出时生成新的工作簿副本。

八列字段固定为：

  列   字段
  ---- ----------
  A    日期
  B    星期
  C    时间
  D    领域
  E    训练任务
  F    负责教练
  G    值班教练
  H    备注

### 10.2 导出规则

-   从现有训练计划导出到上述同一模板。
-   一个日期时段在 Excel 中只占一行。
-   一个时段有多个独立任务时，将多个任务内容合并到同一个"训练任务"单元格，以单元格内换行显示；不得为每个任务增加
    Excel 行。
-   负责教练有多名时，在 F
    单元格内用换行列出；主要教练用"（主）"标记。只有一名负责教练时可不标记或按一致规则标记。
-   "全体"作为独立值，不得与具体教练同时出现。
-   选手自主任务、个人进度、教练反馈和附件不导出到官方计划模板。
-   不增加隐藏工作表或额外列来承载系统数据。

### 10.3 导入规则

-   导入目标是用户已经在 TMS 中创建的空训练计划；导入不负责创建计划。
-   导入与导出使用同一个模板。
-   只读取"训练计划"工作表，忽略"班级课表"。
-   支持部分导入：文件中有多少符合格式的数据就导入多少；可以只有排班信息、只有部分任务、只有部分日期或部分时段，不要求整张表完整。
-   日期和时段是定位时段的必要信息；无法识别日期/时段的行列为错误，不影响其他有效行的预览。
-   日期/星期/值班教练/备注的纵向合并单元格按所属日期向下解析。
-   星期以日期计算结果为准；Excel 星期不一致时给出警告。
-   训练任务单元格为空时，只导入该行其他有效排班信息。
-   训练任务单元格有内容时，整个单元格内容解析为**一个训练任务**，保留换行，不得按换行拆成多个任务。
-   因此，系统导出的多个独立任务在 Excel
    中会合并成多行文本；再次导入时会成为一个任务。这是用户明确接受的非无损往返规则，必须在导入预览/说明中明确提示。
-   单元格内容为空不应覆盖数据库已有内容；导入面向空计划，若目标计划已存在冲突数据，预览时标记冲突，不得静默覆盖。
-   当前模板没有选手范围列，导入的官方任务默认分配给计划创建时的选手快照；需要指定部分选手时，导入后在网页中调整。
-   当前模板没有技能列，技能关联不通过该 Excel 导入/导出。
-   负责教练列支持一个或多个教练；多名教练以单元格换行分隔，主要教练以"（主）"标记；"全体"必须独占。只有一名教练时默认其为主要教练。
-   导入前必须提供解析预览、校验结果和确认步骤；确认后使用事务写入。
-   显示成功、警告、错误和跳过记录；允许有效部分导入，不因单条无效数据丢弃整份文件。
-   导入不能绕过权限、排班审批和时段自动锁定规则。
-   如果导入数据涉及已经锁定的时段，禁止修改该时段，并在预览中明确说明。

### 10.4 模板实现要求

-   先在仓库中查找是否已有该模板资源或 Excel 处理代码。
-   如模板文件尚未进入仓库，按项目资源组织方式将用户提供的模板纳入项目；不要凭空重建一份外观相似但样式不同的模板。
-   使用可靠的 xlsx
    库处理合并单元格、样式复制、行插入和日期值；优先复用项目依赖，确有必要再增加依赖。
-   对新增"早读"行，复制原时段行的行高、单元格样式、边框、对齐和格式；重新建立每一天的日期/星期/值班教练/备注合并区域。
-   导入解析必须兼容模板的合并单元格，不能只读取合并区域的左上角而遗漏后续时段。
-   增加模板结构测试，确保八列、工作表名称、合并布局和四时段输出稳定。

## 11. 建议的数据实体职责

具体模型名称以现有代码为准，不要求机械采用以下名称；重点是职责和关系清晰：

1.  **训练计划**：周期、排班人员、参与选手、计划状态。
2.  **日期/时段排班**：日期、时段、时间快照、领域、负责教练、主要教练、锁定状态；日值班教练和日备注可单独存储或归属于日期记录。
3.  **官方训练任务**：时段、标题、Markdown
    说明、创建者、技能关联、附件、软删除状态。
4.  **任务选手分配**：任务与选手关系、分配快照、当前执行状态、撤销信息。
5.  **状态变更历史**：操作人、时间、前后状态。
6.  **训练进度记录**：任务分配、选手、已完成/掌握内容、未完成/问题、提交时间。
7.  **进度记录修订历史**：保留被编辑前的原始版本及修订者、时间。
8.  **教练反馈**：关联选手任务或个人任务，记录作者、时间、内容。
9.  **选手自主任务**：选手、计划、日期、可选时段、可选领域、标题、Markdown
    说明、可选技能关联。
10. **排班调整申请/审批记录**：申请人、变更前后值、原因、审批人、审批时间、结果。
11. **任务修改审计记录**：操作类型、操作者、时间、修改前后内容、原因。

避免用一个大 JSON
字段替代需要筛选、统计和权限控制的核心关系字段。对于任务来源，必须能明确区分官方任务与个人自主任务。

## 12. 实施阶段

### Phase 0：现状审查与实施设计

-   阅读 `AGENTS.md`。
-   审查训练计划、训练任务、选手、教练、竞赛项目、会议人员选择、表格、附件、审批和审计相关代码。
-   列出现有模型/页面与本计划的差距。
-   识别需要数据迁移的现有训练计划、任务、分配和附件。
-   先输出简短审查结论和实施顺序，再开始修改。

### Phase 1：数据模型与权限基础

-   建立/调整计划、时段、官方任务、任务分配、进度记录、状态历史、反馈、个人任务和审计关系。
-   添加时段时间快照与统一锁定服务。
-   建立服务端权限检查和审批服务。
-   编写迁移及必要的数据迁移脚本。
-   对已有数据制定安全迁移策略，不丢失历史任务和附件。

### Phase 2：计划创建与日程排班

-   计划创建时指定周期、排班人员和参与选手。
-   自动生成每日四个时段。
-   实现一天一行、四时段横向展示、31 行分页、日期选择/全选。
-   实现排班阶段、批量清空、排班定稿和审批调整。
-   实现状态驱动的时段单元格交互。
-   实现四时段统一配置及计划时间快照。

### Phase 3：官方任务编制

-   在计划详情页时段中添加多个任务。
-   实现主要教练权限、全体特殊选项、任务人员分配快照。
-   实现任务搜索、筛选、排序列表。
-   实现 Markdown 说明、任务附件、可选技能关联。
-   实现任务编辑、软删除/清空、交接和完整历史。
-   任务保存即生效。

### Phase 4：选手执行与教练反馈

-   选手查看完整日程，但仅显示分配给自己的官方任务内容。
-   实现四种状态及状态历史。
-   实现时间序列进度记录、Markdown、图片和附件。
-   实现多位负责教练独立反馈。
-   确保时段锁定后进度、状态和反馈仍可继续更新。

### Phase 5：选手自主任务

-   实现选手在计划周期任意日期添加个人任务，包括休息日。
-   日期必选、时段可选、领域可选。
-   实现选手本人编辑/删除。
-   对应负责教练可查看并反馈；其他教练和其他选手不可见。
-   自主任务与官方任务分开统计，但复用合适的进度和反馈基础能力。

### Phase 6：Excel 导入/导出

-   纳入并使用用户原始模板。
-   实现四行/日的导出模板副本。
-   实现单元格内多任务换行导出规则。
-   实现合并单元格解析、部分导入、预览、校验、事务确认。
-   实现导入权限、审批和时段锁定检查。
-   忽略"班级课表"工作表。

### Phase 7：回归测试与文档

-   完成权限、业务规则、导入导出、时区边界、附件隔离和数据迁移测试。
-   检查所有写入入口均执行后端锁定和权限校验。
-   更新相关使用文档、管理员配置说明和开发文档。
-   运行项目要求的格式检查、类型检查和测试；按 `AGENTS.md`
    的测试范围执行，不无故扩大为全项目无关测试。

## 13. 验收标准

### 计划与排班

-   [ ] 计划创建时指定排班人员和选手范围。
-   [ ] 计划周期内自动生成全部日期及四个时段。
-   [ ] 日程视图一天一行、四个时段横向展示。
-   [ ] 31 行分页，日期支持选择和全选。
-   [ ] 每个时段最多一个训练领域。
-   [ ] 多负责教练时必须指定主要教练。
-   [ ] "全体"与具体教练名单互斥。
-   [ ] 排班阶段可以清空重排；定稿后排班变更走审批。
-   [ ] 时段到结束时间自动锁定，服务端不能绕过。

### 官方任务

-   [ ] 任务只在计划详情页管理，不存在独立一级菜单。
-   [ ] 同一时段支持多个独立任务。
-   [ ] 任务列表支持搜索、筛选和排序。
-   [ ] 主要教练可编辑；其他负责教练只读任务定义但可反馈。
-   [ ] 任务修改、软删除、交接均保留历史。
-   [ ] 创建时选手分配范围固化；后续新选手不自动继承历史任务。
-   [ ] 锁定后禁止修改任务定义和人员分配。

### 选手执行

-   [ ] 每名选手的任务状态独立。
-   [ ] 支持未开始、进行中、已完成、未完成。
-   [ ] 已完成状态允许纠正，状态变化保留历史。
-   [ ] 每次进度提交形成独立记录，支持 Markdown、图片和附件。
-   [ ] 教练反馈独立记录作者、时间和内容。
-   [ ] 锁定后仍可补充进度、更新执行状态和填写反馈。

### 个人自主任务

-   [ ] 不建立个人训练计划。
-   [ ] 选手可在计划周期内任何日期添加任务，包括休息日。
-   [ ] 日期必选，时段可选。
-   [ ] 选手本人可管理；对应负责教练可查看和反馈；其他人不可见。
-   [ ] 自主任务不影响官方计划完成率。

### Excel

-   [ ] 只处理"训练计划"工作表。
-   [ ] "班级课表"完全忽略。
-   [ ]
    保留原八列、原有样式和合并布局；每天输出早读、上午、下午、晚上四行。
-   [ ] 一个时段一行；多个任务在同一单元格内换行。
-   [ ] 导入时整个任务单元格解析为一个任务，不按换行拆分。
-   [ ] 支持部分导入和导入预览。
-   [ ] 导入不能覆盖冲突数据或绕过锁定/审批。
