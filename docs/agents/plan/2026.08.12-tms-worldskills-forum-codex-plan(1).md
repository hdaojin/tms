# 1. 产品目标

当前工作方式：

```text
WorldSkills Forum
    ↓
翻译老师按主题翻译
    ↓
复制到 Word
    ↓
发送聊天群
    ↓
信息被拆散成多个文件，连续性和检索性差
```

目标方式：

```text
WorldSkills Forum
    ↓
翻译老师人工复制原文
    ↓
TMS「世赛论坛」翻译工作台
    ↓
Topic → Post → 中文翻译
    ↓
直接发布
    ↓
最新动态 / Topic 时间线 / 搜索 / 筛选 / 未读变化
```

核心原则：

- **TMS 是唯一的正式归档位置。**
- 聊天群以后只承担通知或分享链接，不承担资料归档。
- 数据按论坛真实语义建模，不按 Word 文件建模。
- 一个论坛 Topic 可以持续增加很多 Post。
- 每个 Post 保存英文原文和一份中文翻译。
- Post 可以附带 0..N 个图片或附件；附件属于原始 Post，而不是 Translation。
- 图片/附件优先人工归档到 TMS；无法或不适合下载时允许仅保存原论坛附件 URL。
- 中文默认展示，英文原文按需展开。
- 必须能够追溯原论坛链接、原作者、原发布时间、信息身份，以及可用时的原附件来源链接。
- “专家个人讨论”和“WorldSkills 官方信息”必须在界面上明显区分。
- 用户应能快速回答：“最近论坛有什么新信息？”以及“这个主题后来又发生了什么？”

# 4. 为什么使用独立 APP

仓库中虽然存在 `articles/`，但当前 TMS 的核心需求并不是普通文章发布，而是：

```text
ForumTopic
    ├── ForumPost
    │      ├── ForumTranslation
    │      └── ForumPostAttachment 0..N
    ├── ForumPost
    │      ├── ForumTranslation
    │      └── ForumPostAttachment 0..N
    └── ForumPost
           ├── ForumTranslation
           └── ForumPostAttachment 0..N
```

论坛信息具有以下普通文章不具备的语义：

- 同一 Topic 持续更新；
- 原始帖子时间线；
- 原始作者身份；
- WorldSkills 官方 / Expert 等来源身份；
- 原帖 URL；
- Topic 摘要；
- 用户阅读进度；
- “上次看到这里”；
- 按 Module / 规则 / Marking / Environment 等维度筛选。

因此必须独立建模，避免把通用文章模型改成论坛专用模型。

# 6. 数据模型

## 6.1 `ForumCategory`

用途：Topic 主分类，可由管理员维护。

字段：

```text
name            CharField(100), unique
slug            SlugField(120), unique
sort_order      PositiveIntegerField, default=0
is_active       BooleanField, default=True
created_at      DateTimeField(auto_now_add=True)
```

规则：

- `slug` 可以人工输入；


slug 使用稳定英文值，例如：


不要依赖数据库 conditional unique constraint，以保持 SQLite / PostgreSQL / MySQL 兼容。

- 当 `source_topic_id` 非空时，同一系统内不得重复；
- 精确重复 `source_url` 时给出明确提示，但不要因为 URL 参数变化强行做 URL canonicalization。

## 6.7 `ForumPostAttachment`

用于保存 Forum Post 中偶尔出现的图片、PDF、Office 文档、压缩包或其他允许归档的附件。

**附件属于 `ForumPost`，不要挂到 `ForumTranslation`。**

原因：

- 附件是论坛原帖的一部分；
- 后续即使中文翻译被编辑，原始附件仍然不应改变归属；
- 同一个附件可能同时为英文原文和中文解释提供上下文。

字段：

```text
post                ForeignKey(
                        ForumPost,
                        CASCADE,
                        related_name="attachments"
                    )

kind                CharField(...)
file                FileField(
                        "本地归档文件",
                        storage=PrivateMediaStorage("worldskills_forum"),
                        upload_to=forum_attachment_upload_path,
                        blank=True
                    )

original_filename   CharField("原始文件名", max_length=255)
source_url          URLField("论坛原附件链接", max_length=1000, blank=True)

caption_zh          CharField("中文说明", max_length=500, blank=True)
sort_order          PositiveIntegerField("排序", default=0)

file_size           PositiveBigIntegerField("文件大小", null=True, blank=True)
content_type        CharField("MIME 类型", max_length=255, blank=True)

created_by          ForeignKey(
                        settings.AUTH_USER_MODEL,
                        SET_NULL,
                        null=True,
                        related_name="forum_attachments_created"
                    )
created_at          DateTimeField(auto_now_add=True)
```

### `AttachmentKind`

```text
IMAGE       image       图片
FILE        file        附件
```

### 双模式归档

`ForumPostAttachment` 必须支持：

#### A. 本地归档

```text
file != empty
source_url 可为空或填写
```

用于 Translator 已经从 WorldSkills Forum 下载到原始文件的情况。

#### B. 仅保留来源链接

```text
file = empty
source_url != empty
```

用于：

- Forum 附件需要特殊登录权限；
- URL 为论坛内部页面；
- Translator 暂时不方便下载；
- 文件类型不在本地允许上传列表；
- 只需要保留来源引用。

Model/Form 必须校验：

```text
file 和 source_url 至少存在一个
```

不允许两者同时为空。

### 上传路径

不得使用用户提交的原始文件名作为服务器实际路径。

创建：

```python
def forum_attachment_upload_path(instance, filename):
    ...
```

路径采用日期 + UUID，例如：

```text
2026/08/12/550e8400e29b41d4a716446655440000.pdf
```

完整存储位置：

```text
settings.PRIVATE_MEDIA_ROOT/
└── worldskills_forum/
    └── 2026/
        └── 08/
            └── 12/
                └── <uuid>.<ext>
```

`original_filename` 单独保存原文件名用于 UI 与下载名。

### 文件清理

使用项目现有：

```python
register_file_cleanup_signals(...)
```

注册：

```text
ForumPostAttachment.file
```

保证附件记录或父 Post 删除后，本地文件同步清理。

## 6.8 `ForumTopicReadState`

用于实现：

- 未读信息；
- Topic 新内容；
- “你上次看到这里”。

字段：

```text
user            ForeignKey(settings.AUTH_USER_MODEL, CASCADE)
topic           ForeignKey(ForumTopic, CASCADE, related_name="read_states")
last_viewed_at  DateTimeField()
```

约束：

```text
UniqueConstraint(user, topic)
```

注意：

**判断“新内容”必须使用 `ForumTranslation.published_at`，不要使用论坛原始的 `ForumPost.posted_at`。**

原因：

一个论坛帖子可能 8 月 1 日发布，但翻译老师 8 月 5 日才录入 TMS。对 TMS 用户而言，它应该在 8 月 5 日成为新信息。

# 7. 图片与附件处理方案

Forum 内容仍然以文字为主，但 V1 必须把图片和附件作为正式内容的一部分处理，避免重新退化成“文件散落在聊天群”。

---

## 7.1 基本原则

```text
Forum 原文
   │
   ├── 文字 → original_content
   │
   ├── 图片 → ForumPostAttachment(kind=image)
   │
   └── 文件 → ForumPostAttachment(kind=file)
```

中文翻译仍然放在：

```text
ForumTranslation.translated_content
```

图片本身不建立“翻译后的图片”。

如果图片中存在必须理解的英文：

- Translator 在 `translated_content` 中写对应中文解释；或
- 在附件的 `caption_zh` 中补充中文说明。

V1 不做：

```text
OCR
图片文字自动识别
图片文字自动翻译
图片重绘
```

---

## 7.2 私有存储

本地归档附件必须使用项目已有：

```python
PrivateMediaStorage("worldskills_forum")
```

**禁止使用公开 `MEDIA_ROOT/media/`。**

原因：

- WorldSkills Forum 本身可能需要登录才能查看；
- TMS 的 Forum 内容只面向已登录内部人员；
- 如果将文件放入公开 media，Nginx 直接访问会绕过 Django 登录与权限控制。

# 9. Service 层

创建：

```text
worldskills_forum/services.py
```

不要把多模型事务全部堆在 View 中。

至少实现：

## `create_published_post(...)`

职责：

1. 接收 Topic、表单清洗后的数据、当前用户；
2. `transaction.atomic()`；
3. 创建 `ForumPost`；
4. 创建 `ForumTranslation`；
5. `created_by / updated_by / translated_by` 写当前用户；
6. `published_at = timezone.now()`；
7. 返回 Post。

要求：

- Post 与 Translation 必须原子创建；
- 不允许出现只有 Post 没有 Translation 的正常 Web 工作流数据；
- source ID 去重校验在事务前或事务内完成；
- 对重复数据给中文错误信息。

## `update_published_post(...)`

职责：

1. 同时更新 Post 与 Translation；
2. 保留原 `translated_by`；
3. 更新 Post `updated_by`；
4. 更新 Translation `updated_by`；
5. 不修改 `published_at`；
6. 在事务内完成。

## `mark_topic_viewed(user, topic, viewed_at=None)`

职责：

- `update_or_create()` 用户的 `ForumTopicReadState`；
- 默认使用 `timezone.now()`。

## 查询辅助

可以在 `selectors.py` 或 `services.py` 内提供查询函数，但不要为简单 QuerySet 过度抽象。

如果创建 `selectors.py`，至少包括：

```text
get_published_post_feed(user, filters)
get_topic_timeline(topic)
```

# 15. “你上次看到这里”

进入 Topic 详情时：

1. 在更新阅读状态之前先读取旧的 `last_viewed_at`；
2. 按 `translation.published_at` 把时间线分成：
   - `old_posts`
   - `new_posts`
3. 模板先显示 old_posts；
4. 如果存在 new_posts，在两组之间显示：

```text
──────── 你上次看到这里 ────────
```

5. 再显示 new_posts；
6. 页面上下文准备完成后将该 Topic 当前用户的 `last_viewed_at` 更新为 `timezone.now()`。

第一次进入 Topic：

- 不显示“上次看到这里”；
- 将全部内容正常显示；
- 建立 read state。

注意：

- 分组标准是 TMS `published_at`；
- 时间线实际排序仍按 Forum `posted_at`；
- 这是两个不同维度，不要混淆。

## 30.6 Unread Tests


```text

```

而不是：

```text
post.posted_at
```

再覆盖：

- 查看后创建 read state；
- 第二次进入没有新内容 → 无 divider；

## 30.7 Attachment Tests

覆盖：

### 上传

- 合法 JPG/PNG/PDF/DOCX/ZIP 可以上传；
- 超过单文件限制拒绝；
- 超过 10 个附件拒绝；
- 总大小超过限制拒绝；
- 扩展名与文件签名不匹配时，已有公共 validator 能识别的类型必须拒绝；
- SVG/HTML/JS/EXE 不允许本地上传。

### 私有访问

- 文件实际位于 `PRIVATE_MEDIA_ROOT/worldskills_forum/`；
- 不生成公开 media URL；
- 未登录用户访问 attachment content endpoint 被全局登录 middleware 拦截；
- 登录用户可以访问有效附件。

### Content-Disposition

- JPG/PNG/GIF/WebP → `inline`；
- PDF/Office/TXT/ZIP → `attachment`；
- 响应包含 `X-Content-Type-Options: nosniff`；
- 下载文件名使用 `original_filename`。

### 外部来源

- URL-only Attachment 可以创建；
- 页面显示 Forum 来源链接；
- 页面 HTML 不把外部图片 URL 写入 `<img src>`；
- 服务端不会请求外部 URL。

### 生命周期

- 删除 Attachment 后本地文件被清理；
- 删除 Post 后附件记录与本地文件被清理；
- 创建事务失败不会遗留本次上传的 orphan file。

### 页面展示

- Topic detail 本地图片可以 inline；
- Feed 只显示图片/附件数量，不直接加载所有图片；
- `caption_zh` 正常显示；
- 普通附件显示文件名、大小、下载链接。
