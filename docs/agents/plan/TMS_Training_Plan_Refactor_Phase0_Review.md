## 3. 当前实现与 Plan 的差距及冲突

| 项目 | 当前实现 | Plan 要求 / 建议处理 |
| --- | --- | --- |
| 锁定时机 | `TrainingTask.is_locked` 按选手开始执行判断；审批后还允许人员交接；时段没有时间快照 | 按时段快照结束时间 `now >= end_at` 统一锁定；申请、审批、任务、分配、导入等入口均在事务内复核。执行开始不能替代这个时间规则 |
| 技能修正例外 | ADR 0010、CONTEXT、AGENTS 与 `set_task_skills` 明确允许执行后、归档后修正 | Plan 禁止锁定后修改任务定义，未写技能例外。建议按新 Plan 取消例外，但须确认是否仍将技能整理作为独立例外 |
| 时段领域 | `TrainingScheduleSlot.domains` 多选并另设 `primary_domain` | 每时段最多一个领域；新数据使用单领域，历史多领域须先报告，不能擅取第一个 |
| 任务生效 | 保存草稿，另行发布时分配选手 | 保存即生效，同时固定当次分配名单；更新文档及对应旧测试，不保留额外发布动作作为必经步骤 |
| 计划选手范围 | 计划没有参与选手关系；任务从周期实时成员取默认名单 | 建立计划参与选手关系与创建时快照；普通任务按任务创建时计划成员分配，Excel 默认按计划创建时快照 |
| 任务维护范围 | 指定 `task_managers` 可代填全部时段，创建者也可能拥有排班能力 | Plan 明确管理员/当前主要教练管理任务，全体负责时由管理员或排班人员编制。建议保留角色数据，不继续默认用任务管理员身份越过主要教练范围；需明确“管理员”是否包含既有计划任务管理员 |
| 全体与主教练 | 全体可携带具体教练名单，发布时转成快照；单教练仍需手动指定主要教练 | 输入中全体与名单互斥，持久化的全体快照与输入语义区分；单教练自动成为主要教练 |
| 选手可见范围 | 已发布的计划内任务对计划可见成员开放，不要求当前用户有对应执行分配；选手仍能看到部分历史/审批内容 | 选手仅见本人有效分配任务及本人进度，完整日程框架可见；管理历史及审批服务端完全隔离，筛选结果也不能泄露未分配任务 |
| 日程布局 | 一时段一行，28 条分页，有类型与操作列，保留“补齐日期框架” | 一天一行、四时段横向、31 个日期分页、日期全选与清空；自动生成框架，删除补齐按钮；另提供任务粒度列表 |
| 清空 | 取消任务已有审计，但未提供 Plan 所需排班阶段批量清空 | 排班阶段清空排班；定稿后只清空有权管理的任务，全部受时段锁定和预览确认约束 |
| 执行状态 | 已分配、进行中、已完成、部分完成、受阻、已取消；撤销混在状态中 | 四种执行状态与逻辑撤销分离，增加状态历史；旧“受阻”不能擅自解释为本次已结束的“未完成” |

## 5. 数据迁移与回滚方案

1. 保留已应用的 `0010`，从后续新迁移增加结构。先添加可兼容旧记录的字段/关系，再做经过验证的回填及约束收紧；不删除旧任务、执行、附件或日志关联。
2. 新计划要求管理员先完整配置四时段起止时间；不预置讨论示例时间。创建时固化 timezone-aware 的时段时间，修改系统配置不改变旧计划。
3. 旧计划没有时间快照，无法推断历史实际时段时间。先只读列出待整理对象，再经明确配置回填，不能把今天配置声称为过去创建时的真实快照；未完成整理的记录禁止开放新定义写入。具体兼容/补录流程在 Phase 1 定稿。
4. 计划参与选手与创建快照是新增事实：既有任务分配保持不动；不能把当前周期成员当成旧计划创建时的真实名单。已有分配可作为已知历史事实保留，其他范围由管理员明确整理。
5. 无时段的旧任务保留原主键和历史身份，不猜测时段；已有执行/日志关联保持。历史多领域数据先列异常清单并人工整理，再收紧单领域约束，不截断或删除领域。
6. 执行状态迁移保留旧值及撤销事实。“已分配”可对应“未开始”；“部分完成/受阻”须保留原始状态并确认转换语义，不能无痕合并。取消增加操作人、时间、原因；无法追溯的旧值不伪造。
7. 旧执行汇总文本可以标记为“历史汇总导入”的初始进度；当前反馈保留原作者、时间。只能保留现存事实，不能虚构旧状态变化、进度修订或多教练反馈历史。
8. 旧执行附件仍保留原路径、记录和所属执行；如关联迁移进度，保存可核对的旧记录映射，不移动或复制大文件。已有文件清理 signal 不得在迁移中误删文件。
9. 迁移测试从旧 migration state 创建含任务、执行、附件及日志关联的数据，验证新迁移后主键、内容、时间、引用和文件路径完整，并覆盖异常/回滚分支。
10. 结构迁移可在安全情况下反向执行，但生成新的进度、反馈、状态历史后不可无损压回旧字段；上线回退依赖升级前数据库和私有文件备份，不承诺反向 migration 能保留旧系统无法表达的数据。此次不执行部署、清库、生产迁移或权限重配。

## 6. 待明确事项与外部资源

- 技能关联是否保留执行后/归档后的独立修正例外；建议遵循新 Plan 的统一锁定，需同步旧 ADR。
