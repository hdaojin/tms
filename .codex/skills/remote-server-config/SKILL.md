# 远程服务器配置

目标服务器固定为 `ecs-user@8.134.199.121:2222`（`test.itnsa.cn`）。使用当前 Windows `demo` 用户环境中已有的 OpenSSH 配置、ssh-agent 或默认身份文件认证；绝不读取、打印、复制、保存或提交私钥、口令、令牌和 `.env` 内容。

`ecs-user` 可使用 `sudo`，但只在单条确有必要的命令上提升权限。不要进入持续的 root shell，也不要默认修改 SSH 登录策略、主机密钥、用户账户、防火墙或网络访问规则；这些操作须由用户在当前请求中明确授权。

## 连接前检查

1. 先确认请求的实际目标与影响范围。提示词含糊、涉及生产服务、数据删除、账号/网络/SSH 政策或不可逆操作时，先询问，不作假设。
2. 通过 `ssh -G -p 2222 ecs-user@8.134.199.121` 仅检查客户端最终连接配置；只报告主机、端口、用户和身份文件路径是否可用，绝不显示身份文件内容。
3. 首次使用本会话时执行只读预检，使用 `BatchMode=yes`、`ConnectTimeout=10` 和 `StrictHostKeyChecking=yes`。未知或变化的主机指纹、认证失败或连接超时均应停止，并将其作为连接问题报告给用户；不得自动接受指纹或降低主机密钥校验。
4. 将 SSH 连接结果、远程命令退出状态与功能验证结果分别报告。连接成功不等于配置已正确生效。

## 配置工作流

1. 先执行与任务相关的最小只读检查，识别操作系统、服务状态、当前配置、依赖关系和回滚条件。不得在探查阶段修改远程主机。
2. 给出变更计划：目标、将执行的确切远程命令、是否使用 `sudo`、预期影响、验证方式及可用回滚方式。
3. **任何写入远程主机的操作前，必须取得用户对本轮计划的明确确认。** 包括软件安装/卸载、文件写入、服务重启、数据库或账户变更、`sudo` 写操作和配置重载。确认只授权已展示的计划；任务范围变化时重新确认。
4. 获确认后，以最小变更执行。命令必须安全地传递参数，不将用户输入交给 `eval`、未加引号的 shell 拼接或不受控重定向。修改前保留可恢复的原配置副本（若任务和磁盘空间允许），并记录其位置但不泄漏敏感内容。
5. 立即执行功能性验证和最小回归检查；若失败，停止后续变更，说明实际结果与安全的恢复建议。仅在用户明确要求时才执行恢复操作。

## 禁止事项

- 不绕过认证、主机密钥校验或 sudo 授权；不要求用户在聊天中提供私钥或密码。
- 不将凭据或敏感配置写入仓库、日志、终端输出、补丁或技能文件。
- 不因“配置服务器”的泛化描述而自动部署代码、迁移数据库、开放端口、重启无关服务或修改其他主机。
- 不把本技能视为持久授权：每次远程写操作均以该次用户明确确认的范围为准。
