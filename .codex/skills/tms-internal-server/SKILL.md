# TMS Internal Server

## 目标与连接

- 连接目标固定为 `demo@10.21.57.72:22`，直接使用 IP，不使用 `tms.itnsa.cn` 建立连接；`10.21.57.5` 不作为备用地址。
- 使用 Windows `demo` 用户现有 OpenSSH 配置、ssh-agent 或默认身份文件，不复制或重新生成密钥。
- `test.itnsa.cn` 是另一个目标，使用项目的 `tms-test-server` Skill；不能混用两台服务器的地址、账号或端口。

从 PowerShell 调用 Windows OpenSSH，显式指定用户配置及 known_hosts，避免自动化进程使用不同的 home：

```powershell
ssh -F 'C:\Users\demo\.ssh\config' -p 22 `
  -o BatchMode=yes -o ConnectTimeout=10 -o StrictHostKeyChecking=yes `
  -o UserKnownHostsFile=C:/Users/demo/.ssh/known_hosts `
  demo@10.21.57.72 '<只读或用户已授权的远程命令>'
```

需要核对客户端配置时使用相同目标的 `ssh -G`，仅提取 hostname、user、port 和身份文件路径等必要字段，不输出完整配置。核实最终 hostname 为 `10.21.57.72`、user 为 `demo`、port 为 `22`；若客户端配置将其改写为其他目标，先澄清，不自动连接域名或其他服务器。

## 执行流程与授权

1. 用户明确要求的操作即为该次授权。例如“安装指定软件”或“重启指定服务”允许检查后执行对应操作，无需对同一范围重复索要确认。仅要求检查时不得修改；创建或调用本 Skill 本身不构成任意远程修改的长期授权。
2. 每个会话首次连接先做最小只读预检，确认远程身份、主机和相关服务现状。用户说明 Linux `demo` 具备免密 sudo；以 `sudo -n true` 核实可用性，不将其视为所有命令均必然获准的证明。
3. 执行前简要说明具体操作及影响。普通操作直接在已授权范围内继续；目标含糊、需要扩大范围，或操作具有用户尚未说明的破坏性影响时，先展示确切命令、影响和可恢复方案，取得必要确认再执行。
4. 按需在单条命令使用 `sudo -n`，不打开持续 root shell，不修改 sudo/SSH 策略来绕过失败。修改配置前在权限和磁盘空间允许时保留可恢复副本；备份位置可以报告，秘密内容不能输出。
5. PowerShell 参数与远程 Linux shell 参数分别正确引用；避免 `eval`、未引用的用户输入和不受控命令拼接。复杂命令先组织成可审阅脚本，处理编码和换行后再传递，不把秘密嵌入脚本或日志。
6. 执行后检查退出状态和实际功能。失败时停止依赖该步骤的后续操作，报告实际状态；重试或恢复只限于已授权范围，不扩大变更。分别说明连接、命令执行与功能验证结果。

## 停止条件与秘密保护

- 未知或变化的主机密钥必须停止。先由用户通过可信渠道核实指纹，再按明确授权维护 known_hosts；不得自动接受指纹、删除旧记录或关闭严格校验。`ssh-keyscan` 的输出本身不能证明服务器身份。
- 认证失败、超时或 `sudo -n` 失败时报告原因，不改用口令交互、不尝试其他账号或主机、不修改认证配置。
- 不读取、打印、复制、保存或提交私钥、密码、令牌和 `.env` 秘密；检查配置或日志时只提取必要的非敏感结果。不要要求用户在聊天中提供凭据。
- 不因连接成功而顺手部署、迁移数据库、重启无关服务或调整账号、网络、防火墙。
